# gRPC-контракт прогнозирования

[forecast.proto](tramcast/forecast/v1/forecast.proto) — общий контракт Python-сервера и Go-клиента. Полный путь метода: `/tramcast.forecast.v1.ForecastService/Predict`. Один unary RPC принимает `PredictRequest` и возвращает `PredictResponse` с массивом `PredictionPoint`.

Python выполняет inference с одним фиксированным комплектом модели и данных. Go управляет очередью, вызывает RPC из фонового обработчика, проверяет ответ и сохраняет прогноз. ID задания, версия прогноза, номер попытки и аренда остаются внутри Go. Часовой пояс контракта — `Europe/Moscow`.

## Запрос и ответ

| Запрос | Назначение |
| --- | --- |
| `route_number` | Номер маршрута, например 50; Go получает его из справочника по внутреннему `route_id` |
| `forecast_from`, `forecast_to` | Полный горизонт версии, полуинтервал `[from, to)` |

| Ответ | Назначение |
| --- | --- |
| `model_version` | Непустой ID фактически использованной модели и её настроек |
| `dataset_version` | Непустой ID снимка данных, связанного с загруженным комплектом |
| `points` | Все часы периода; у каждой точки есть `hour_start` и `boardings` |

Python получает версии из метаданных загруженных артефактов. `dataset_version` описывает данные обучения и дополнительные входные снимки, если они используются при inference. Если данные нужны только для обучения, этот ID хранится в метаданных модели; загружать обучающий датасет ради RPC не требуется. Один вызов использует один неизменяемый комплект артефактов.

Go сохраняет контекст вызова: задание, маршрут, версию прогноза, номер попытки и ожидаемые версии артефактов. Ответ unary RPC относится к этому вызову, поэтому повторять служебные ID и маршрут в ответе не требуется. Go сопоставляет `model_version` и `dataset_version` ответа с закреплённой записью `forecast_versions`; при несовпадении весь результат отклоняется и задание завершается неповторяемой ошибкой.

После замены комплекта в Python уже сохранённые прогнозы старых версий остаются доступны из PostgreSQL. Для нового расчёта старой версии нужен соответствующий комплект артефактов; текущий RPC не выбирает его по ID. Возвращать новый расчёт под старой версией нельзя.

## Правила проверки

- Все поля запроса и ответа обязательны по прикладному контракту. Protobuf описывает типы; проверки положительного номера маршрута, непустых ID артефактов, диапазонов и связей выполняются приложениями.
- `Timestamp` должен присутствовать, находиться в допустимом диапазоне Protobuf и иметь `nanos = 0`. Границы и точки выровнены по началу часа в `Europe/Moscow`; `forecast_from < forecast_to`.
- Go передаёт полный горизонт закреплённой версии, даже если пользователь запросил один день. Python проверяет поддержку этого периода загруженными артефактами и ограничение размера расчёта. Лимиты сторон должны позволять 1 464 часа на маршрут для текущего MVP.
- Успешный ответ содержит точную сетку `[from, to)` в порядке возрастания, без пропусков, дублей и лишних часов. Проверки одного количества точек недостаточно. Ночные нули и 1 464 нулевые точки маршрута № 5 сохраняются; неизвестный маршрут не превращается в нулевой прогноз.
- `boardings` присутствует и лежит в диапазоне `0..9223372036854775807`. Python проверяет конечность выхода модели, ограничивает его снизу нулём и округляет half-up: `0.5 → 1`, `1.5 → 2`. Go не округляет повторно; дневные суммы складываются из опубликованных часов.
- Go сверяет фактические версии артефактов с версией прогноза, а каждую точку — с запрошенным периодом. Маршрут и служебные ID берутся из сохранённого контекста вызова. Перед публикацией Go проверяет актуальность попытки и аренды в PostgreSQL. Некорректный ответ целиком отклоняется до записи в БД.

`optional int64 boardings` сохраняет присутствие нулевого значения. В сгенерированном Go-коде с Open Struct API нужно сначала проверить `point.Boardings != nil`, в Python — `point.HasField("boardings")`. Один getter не отличает отсутствие от нуля. [Правила присутствия полей Protobuf](https://protobuf.dev/programming-guides/field_presence/).

Например, для московского ноября–декабря 2025 года границы в UTC — `2025-10-31T21:00:00Z` и `2025-12-31T21:00:00Z`. Ответ содержит 1 464 точки; последняя — `2025-12-31T20:00:00Z`, то есть 31 декабря, 23:00 по Москве. Дату, час и день недели для интерфейса вычисляет Go.

## Ошибки и повторы

Ошибки передаются стандартным статусом gRPC. Отдельного поля `error` и частичного успешного ответа нет. Следующая таблица задаёт соглашение проекта на основе [статусов gRPC](https://grpc.io/docs/guides/status-codes/).

| Статус | Ситуация | Действие Go |
| --- | --- | --- |
| `INVALID_ARGUMENT` | Некорректные поля, границы или превышен прикладной лимит числа часов | Завершить задание ошибкой |
| `NOT_FOUND` | Неизвестный или неподдерживаемый номер маршрута | Завершить задание ошибкой |
| `FAILED_PRECONDITION` | Настроенные артефакты отсутствуют, несовместимы, повреждены либо не поддерживают запрошенный период | Завершить задание ошибкой |
| `UNAVAILABLE` | Временная недоступность сервиса или заняты все разрешённые обработчики Python | Вернуть в очередь с задержкой в пределах лимита попыток |
| `DEADLINE_EXCEEDED` | Истёк deadline RPC | Ограниченный повтор через очередь |
| `CANCELLED` | Вызов отменён | Учитывать причину отмены; при потере аренды прекратить любые записи |
| `RESOURCE_EXHAUSTED` | Исчерпан ресурс или превышен транспортный лимит сообщения | Завершить задание ошибкой; не считать любую такую ошибку временной |
| `INTERNAL`, остальные неожиданные статусы | Ошибка вычисления, нарушенный контракт или конфигурация | Завершить задание ошибкой, записать диагностику |

Неправильный ответ со статусом `OK` также считается неповторяемой ошибкой контракта. Текст ошибки служит диагностикой; решения о повторах не зависят от разбора строки сообщения. Публичную HTTP-ошибку Go формирует отдельно.

Переходы задания разрешены только его текущему владельцу с действующей арендой и номером попытки. Для `CANCELLED` при остановке Go обработчик оставляет восстановление очереди механизму истечения аренды; необъяснимая отмена при действующем владении завершает попытку неповторяемой ошибкой.

Deadline фонового RPC не зависит от HTTP-запроса браузера. Python должен учитывать отмену во время вычислений. При повторе возможен повторный inference, а согласованную публикацию защищает Go. Автоматические повторы и hedging на уровне приложения gRPC не настраиваются: бюджетом попыток управляет очередь PostgreSQL. [Поведение deadlines](https://grpc.io/docs/guides/deadlines/).

## Генерация

Исходник хранится только в `proto/`; обе стороны генерируются из него. Сгенерированные файлы вручную не редактируются. Команды ниже выполняются из корня репозитория.

### Go

Нужны `protoc`, его стандартные include-файлы, `protoc-gen-go` и `protoc-gen-go-grpc` в `PATH`. `go_package` соответствует модулю `github.com/r0mbeg/TramCast/backend`, описанному в `backend/go.mod`.

```text
make proto-generate-go
```

Команда генерирует только Go-код через `protoc`, который проверяет синтаксис и импорты схемы. Команду компилятора можно переопределить переменной Make `PROTOC`. Проверки номера маршрута, версий артефактов, временной сетки и значений выполняются приложениями Go/Python.

Без Make:

```text
protoc --proto_path=proto --go_out=backend --go_opt=module=github.com/r0mbeg/TramCast/backend --go-grpc_out=backend --go-grpc_opt=module=github.com/r0mbeg/TramCast/backend proto/tramcast/forecast/v1/forecast.proto
```

Результат в `backend/internal/gen/tramcast/forecast/v1/`: сообщения `forecast.pb.go` и gRPC-интерфейсы `forecast_grpc.pb.go`. Рабочий Go-клиент использует `NewForecastServiceClient`; преобразование и валидация остаются в `internal/features/forecasts/predictor/grpc`.

Runtime-зависимости `google.golang.org/protobuf` и `google.golang.org/grpc` закреплены в `backend/go.mod`. Сгенерированный код хранится в репозитории; при изменении `.proto` его нужно обновить той же командой. Версии генераторов указаны в заголовках сгенерированных файлов. [Пути генерации Go](https://protobuf.dev/reference/go/go-generated/#compiler-invocation).

### Python

В окружении ML-приложения нужен `grpcio-tools` и совместимые runtime-зависимости `grpcio` и `protobuf`. Создайте каталог вывода `ml/generated`: в PowerShell — `New-Item -ItemType Directory -Force ml/generated`, в Linux/macOS — `mkdir -p ml/generated`.

```text
python -m grpc_tools.protoc --proto_path=proto --python_out=ml/generated --pyi_out=ml/generated --grpc_python_out=ml/generated proto/tramcast/forecast/v1/forecast.proto
```

Результат в `ml/generated/tramcast/forecast/v1/`: `forecast_pb2.py`, `forecast_pb2.pyi`, `forecast_pb2_grpc.py`. Реализация наследует `ForecastServiceServicer` и регистрируется через `add_ForecastServiceServicer_to_server`. [Генерация Python gRPC](https://grpc.io/docs/languages/python/basics/#generating-client-and-server-code).

Каталог `ml/generated` должен входить в путь импорта Python. Для локального запуска из корня в PowerShell установите `$env:PYTHONPATH = (Resolve-Path ml/generated).Path`, в Linux/macOS — `export PYTHONPATH="$PWD/ml/generated"`. После этого импорт доступен как `from tramcast.forecast.v1 import forecast_pb2, forecast_pb2_grpc`. При упаковке ML-приложения этот namespace-пакет нужно включить в его сборку.

## Изменения контракта

Номера существующих полей не меняются и не используются повторно. При удалении поля резервируются его номер и имя через `reserved`. Новые поля не должны становиться обязательными для существующих клиентов; несовместимые изменения получают новый пакет `tramcast.forecast.v2`.
