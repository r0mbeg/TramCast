Подготовка этих входов включает родительские модели, учителей и внешние признаки.
Они зафиксированы офлайн. Новая история или новый период требуют их согласованной
пересборки в полигоне, а не изменения одной даты в JSON. Runtime не выполняет
Optuna-поиск и не выдаёт готовый CSV за вызов модели.

Рабочий режим — CUDA для расчёта, CPU для выдачи кэша. Шесть компонент
считаются последовательно в режиме `low_memory` и `memory_saving_mode`.
Численные различия при смене устройства/среды возможны; score посылки 030 не является
новой оценкой качества свежего пересчёта. См. [протокол и ограничения](../../docs/FINDINGS.md).
