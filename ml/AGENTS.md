# ML: действующие правила

Соблюдай корневой [контракт](../AGENTS.md) и Ponytail full. До изменения кода представляй план; не создавай коммит без просьбы пользователя.

Текущая цепочка данных и моделей, входы 030 и ограничения пересборки описаны в [docs/PIPELINE.md](docs/PIPELINE.md). Читай её перед изменением подготовки или рецепта и обновляй при изменении подхода; она описывает реализацию, а не заменяет нормативный контракт.

- `lab/` — действующий полигон для продолжения исследований. Сохраняй протоколы, положительные и отрицательные результаты. Старые команды и бюджеты не являются поручением возобновлять задания. Сервис не импортирует лабораторный код.
- Выбранный пользователем основной рецепт — **030, TabPFN hourly profile correction поверх подготовленного 029**. Chronos 002 остаётся контрольным сохранённым результатом. Не подменяй рецепт 030 чистым Chronos или готовым CSV при заявленном пересчёте.
- `recipes/tabpfn-030/` — подготовленные входы, параметры и хеши; `models/` — отдельно устанавливаемые веса. Подготовка истории, родительских прогнозов и признаков остаётся офлайн. В runtime нет поиска гиперпараметров или обучения foundation-модели. TabPFN fit задаёт контекст на подготовленных примерах, predict вычисляет поправки.
- Офлайн-пересборка — `preparation/build.py`, [инструкция](docs/PREPARATION.md): новая история с января 2025 и следующие 61 сутки, отдельный каталог выпуска, обязательное покрытие внешних источников. Старые промежуточные прогнозы не переиспользуются; TimesFM-квантили — только при точном совпадении входов и метаданных. Новый пакет не переключает сервис и не подтверждает качество автоматически.
- Go/PostgreSQL — источник опубликованных прогнозов, владелец очереди и версий. SQLite внутри ML — удаляемый локальный кэш дорогих вычислений. Сетевая файловая система/общий SQLite между хостами не поддерживаются.
- Рабочее развёртывание — один компьютер с NVIDIA RTX 3070 8 ГБ: холодный расчёт на GPU, выдача кэша на CPU. Один ML-сервис, один одновременный расчёт; при попадании в кэш дочерний процесс и CUDA не запускаются. CPU-режим расчёта оставлен для диагностики, не является рабочей настройкой.
- Один процесс использует один неизменяемый рецепт. Его model_version зависит от весов, кода расчёта, библиотек, устройства, параметров и поколения; dataset_version — от подготовленных входов и периода. Изменение входов требует нового согласованного пакета и перезапуска. Не меняй файлы под прежними идентификаторами.
- Кэш содержит полный горизонт всех маршрутов. Промах запускает один расчёт, повторный запрос/срез не вызывает модель заново. SQLite-транзакция предотвращает одновременный расчёт для общей локальной БД; ошибки и отмена не публикуются.
- Ручной пересчёт выпускает конфиг нового поколения. Старые результаты сохраняются; Go регистрирует новую версию. Автоматического переключения версии внутри RPC нет.
- `ml/compose.yaml` — самостоятельная поставка без БД и корневого `.env`; `replay` отдаёт проверенный `bundles/030/` под отдельным ID, `gpu` пересчитывает рецепт. `ML_CONFIG` задаёт текущий конфиг для сервера и административных CLI-команд; явный `--config` имеет приоритет. Код передаётся через GitHub без отдельного архива; инструкция запуска — `docs/HANDOFF.md`.
- Сохраняй [gRPC-контракт](../proto/README.md): полная сетка, Moscow, int64, half-up один раз, нули маршрута 5 и часов 1–4. Сервис наблюдает отмену, завершает дочерний расчёт и не сохраняет частичный ответ.
- Период поставочных входов — ноябрь–декабрь 2025, максимум 1464 часа. Офлайн-builder поддерживает перенос следующих 61 суток с обновлёнными снимками; автоматическая загрузка источников и год — [следующие этапы](docs/ROADMAP.md). Для года нужны новые входы, согласованные лимиты и честная маркировка сценария.
- Не коммить веса, кэш и сырые персональные данные. Сохраняй лицензию и атрибуцию TabPFN. Checkpoint legacy pickle допускается только с закреплённой проверенной SHA256, не из пользовательского RPC.
- Проверка: `make test-ml-service PYTHON=<абсолютный путь>`. Реальное качество/производительность модели и быстрые тесты кэша — разные результаты; не выдавай тестовый вычислитель за вызов TabPFN.
- Отдельная остановочная ветка — `lab/stop_forecast/`: для проверяемого прогноза сначала реальные связанные stop observations и независимая проверка. По уточнению пользователя разрешены отдельные модели обучения по агрегатам и байесовские сценарные исследования до получения разметки; новый кандидат может быть независим от 030. Такие сценарии не считаются проверенным остановочным прогнозом. До получения разметки сохраняются аудит, unassigned ledger и статус unavailable; искусственные остановочные метки из маршрутных сумм запрещены. Рецепт 030 и runtime не меняются. Протокол и проект схемы — в каталоге исследования.
- Дальнейший сбор остановочной ветки ограничен существующими файлами и доступными интернет-источниками: организаторы пока не могут предоставить новые данные. Не строить продолжение на ожидании закрытых выгрузок или полевого сбора. Новый период пилота разрешён, но текущие интернет-данные нельзя автоматически связывать с оплатами 2025. Ограничения и следующий исследовательский шаг — [OPEN_DATA_ONLY.md](lab/stop_forecast/OPEN_DATA_ONLY.md).
- Новое продуктовое решение: пользователь выбрал энтропийное сценарное распределение маршрутного прогноза по остановкам для приложения. Допустим выпуск явно обозначенных расчётных оценок без заявления о проверенной остановочной точности; дополнительные выгрузки не являются условием этой версии. [Решение](lab/stop_forecast/APP_ESTIMATE_DECISION.md) и [готовый локальный пакет E-v1](lab/stop_forecast/APP_PACKAGE.md): 97 позиций №12, 61 день, исходные доли B/F, uniform prior, lambda=1, точный баланс округления. География/допустимость посадок приняты условно, stop accuracy отсутствует. Пакет проверен и воспроизводим; интеграция Go/UI не выполнялась.
- Сценарная функция расширена на [все 10 целевых маршрутов](lab/stop_forecast/NETWORK_PACKAGE.md): 604 позиции, 884 256 строк, неизменные маршрутные итоги 030. Prior использует расстояния до архивных входов метро и равномерную составляющую; исходные B/F-доли есть только для 1/7/11/12, для остальных положительных маршрутов применяется географический сценарий без обученных остановочных долей, для 5 — нулевой fallback. OSM exit-only обнулены условно по позднему снимку. Входы и выпуск передаются через GitHub без ZIP; E-v1 №12 сохранён, backend/frontend не менялись, остановочная точность не измерена.
