# Интеграция ML-сервиса

Основной рецепт — **030**: TabPFN корректирует почасовой профиль подготовленного базового прогноза 029. `runtime/model_030.py` заново выполняет fit/predict на закреплённых примерах и собирает целые почасовые значения. Подготовка этих примеров и базового прогноза остаётся вне RPC. [Запуск, установка весов и ручное обновление](../README.md).

[Инструкция запуска из репозитория](HANDOFF.md) содержит команды установки весов, GPU-режима и проверки API без GPU.

## Поток запроса и ответственность

1. Go находит опубликованный результат в PostgreSQL по версии, маршруту и периоду и отдаёт его интерфейсу.
2. Если результата нет, Go создаёт/переиспользует задание для маршрута и полной версии горизонта. Очередь и повторы находятся только в Go.
3. Python проверяет маршрут, границы и период закреплённого рецепта, затем ищет результат вычисления в SQLite.
4. При промахе Python получает локальную блокировку записи, повторно проверяет кэш и запускает дочерний процесс TabPFN. Считается весь подготовленный горизонт всех десяти маршрутов, поскольку рецепт 030 использует совместные признаки. Остальные запросы переиспользуют результат.
5. После полной проверки результата Python атомарно записывает кэш и возвращает запрошенный маршрут/срез. Go сверяет версии и сетку и транзакционно публикует результат по своим правилам fencing.

PostgreSQL — источник опубликованной истины. SQLite — удаляемый ускоритель; потеря файла потребует пересчёта, но не потери опубликованных прогнозов. SQLite должен находиться на локальном диске/volume одного хоста. Один cache-файл допускает несколько процессов, но сериализует холодные расчёты; несколько хостов потребуют координации в Go, не общей БД SQLite на сетевом диске. Очистка старых cache-файлов пока выполняется оператором, автоматическое вытеснение не реализовано.

## Неизменяемые версии

Выполнить `service.py --describe` с тем же интерпретатором, конфигом и устройством, что используются сервером. Результат содержит `model_version`, `dataset_version`, `forecast_from`, `forecast_to`, `history_end`, зону и маршруты. Именно эти ID backend закрепляет в `forecast_versions`.

`model_version` учитывает проверенные веса, код расчёта, версии библиотек, устройство/архитектуру, seed, параметры и поколение. `dataset_version` — контрольные суммы подготовленных входов, происхождение истории и период. Путь к файлу не является идентификатором данных. Снимок признаков читается в память при старте и не обновляется посреди запроса; checkpoint проверяется перед и после расчёта.

Ручное обновление: `service.py --refresh <новый-конфиг.json>` создаёт отдельный конфиг с новым поколением и завершает команду. Файл не перезаписывается. Затем оператор получает его ID через `--config ... --describe`, согласует новую версию в Go и запускает процесс с этим конфигом. Опциональный `--config ... --warm-cache` пересчитывает и заполняет кэш до переключения сервиса; иначе это делает первый запрос; старые версии и кэш остаются. Команда не меняет уже работающий процесс и не создаёт запись в БД Go. Административная кнопка/новый RPC для этого ещё не реализованы.

Текущий PredictRequest не принимает ID модели. Поэтому процесс закреплён за одним конфигом; смена процесса требует согласования с Go. Ответ другой версии должен быть отклонён целиком, а не опубликован в старое задание. Горячий выбор разных моделей в одном RPC — отдельное изменение контракта.

## Период, данные и результат

Подготовленный пакет 030 покрывает `[2025-11-01T00:00:00+03:00, 2026-01-01T00:00:00+03:00)`. Поддержаны номера 1, 5, 7, 11, 12, 17, 25, 26, 28, 50; один RPC возвращает 1–1464 часа одного маршрута. Номер 5 и часы 1–4 явно нулевые. Для маршрута 5 модель не вызывается даже при пустом кэше, поскольку нулевой fallback закреплён контрактом. Это успешные валидации, не заполненность вагона.

Итоговая поправка смешивается с базой в долях 0.5/0.5, затем применяется half-up. Суточные и месячные суммы складываются из опубликованных целых часов. Переключение масштаба просмотра не меняет модель и не запускает пересчёт.

`recipes/tabpfn-030/inputs.npz` содержит обучающие/будущие признаки и базис, но не сохранённые выходы TabPFN. `base.csv` — подготовленный float-прогноз 029. Сам результат 030 в поставку рецепта не включён. Новая история требует пересборки согласованных входов в полигоне; нельзя заменить один SHA истории и объявить старые признаки обновлёнными.

## Ошибки и ресурсы

- `INVALID_ARGUMENT`: нецелые часы, отсутствующие timestamps, недопустимая длина.
- `NOT_FOUND`: неизвестный маршрут.
- `FAILED_PRECONDITION`: период вне рецепта, нарушенные входы или ошибка модели. Повреждённый сохранённый bundle также даёт этот статус.
- `UNAVAILABLE`: недоступное хранилище, лимит времени вычисления или занятый построитель ответа; Go применяет ограниченные повторы.
- `RESOURCE_EXHAUSTED`: транспортный предел одновременных RPC.
- `CANCELLED`/`DEADLINE_EXCEEDED`: ожидание и вычисление прекращаются; дочерний процесс завершается, SQLite-транзакция откатывается. Другой ожидающий запрос может начать новый расчёт.

Четыре RPC-потока, максимум восемь одновременных RPC, запрос до 64 KiB, ответ до 4 MiB. Лимит дочернего вычисления задаёт конфиг (сейчас 900 секунд); клиентский deadline ограничивает его дополнительно. Пример клиента по умолчанию имеет 5 секунд, поэтому для холодного расчёта используйте `--timeout 900`. Рабочий режим — GPU для расчёта, CPU для выдачи кэша; локальный CPU-прогон превысил 900 секунд. API Go работает через асинхронное задание.

Один процесс сервиса обслуживает оба пути. CUDA загружается только дочерним вычислителем; после расчёта процесс завершается и освобождает видеопамять. Шесть поправок TabPFN считаются последовательно с экономией памяти. Целевой хост — RTX 3070 8 ГБ; годовой горизонт и одновременные тяжёлые приложения требуют отдельного измерения. Для выдачи уже рассчитанного кэша сохраняются тот же конфиг и версии библиотек; смена `device` на `cpu` меняет идентификатор модели и создаёт другой ключ кэша.

При ошибке или отмене частичный/невалидный результат в кэш не попадает. При повреждении строки кэша сервис заново вычисляет её под блокировкой. Кэш не подменяет ошибку нулями и не переключается автоматически на Chronos.

## Контрольный режим и дальнейшее развитие

`--bundle .../bundles/002/forecast_bundle.json` явно включает выдачу прежнего Chronos CSV без вызова модели. `002` — номер посылки; результаты исторического микробенчмарка относятся только к этому режиму. Они не характеризуют TabPFN inference. [Исторические измерения](../lab/artifacts/methodology_20260927/REPORT.md).

Внешние источники, новые даты, несколько рецептов, административный пересчёт через backend и годовой сценарий — [следующие этапы](ROADMAP.md). Снимки внешних данных должны готовиться до вычисления и получать отдельную версию; текущий Predict не обращается в интернет.
