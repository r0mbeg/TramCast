## Кэш и контракт

`make test-ml-service` проверяет сетку и значения контрольного пакета 002,
ошибки gRPC, клиент, контрольные суммы, постоянный кэш, одновременные промахи
из потоков и процессов, повтор после перезапуска, повреждение строки кэша,
ручное новое поколение, отмену ожидания и завершение дочернего процесса.
Проверка пути inference использует счётчик вызовов вместо тяжёлой модели:
один расчёт обслуживает все маршруты и срезы; маршрут 5 сразу возвращает нули.
Этот тест не выдаётся за реальный вызов TabPFN; он проверен отдельно выше.

Окончательный Docker-образ собран на Linux/arm64 с закреплёнными зависимостями;
Compose с резервированием одной GPU прошёл проверку конфигурации. В контейнере
без GPU и без сети выполнена дополнительная проверка: CSV реального GPU-прогона
помещён в тестовый кэш, затем все 14 640 значений прочитаны через gRPC после
повторного открытия SQLite. Конфиг оставался `device=cuda`, вызов модели был
запрещён проверкой, модуль torch не импортировался. Ответ за полный горизонт
одного маршрута занимал 3–138 мс в десяти последовательных запросах; нижняя
граница относится к нулевому маршруту 5. Это проверка CPU-выдачи кэша, не SLA
и не GPU-тест Docker на целевом x86-хосте. Скрипт сохранён с замерами.

Локальный полный CPU-расчёт с двумя потоками прерван лимитом 900 секунд.
Частичный результат в SQLite не появился. Поэтому рабочий конфиг использует
`device=cuda`; CPU остаётся для выдачи кэша и диагностики.
