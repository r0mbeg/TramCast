# Обновление истории и перенос 61-дневного прогноза

`ml/preparation/build.py` выполняет офлайн-пересборку семейства 030: история →
TimesFM-признаки → базовые модели → 021 → 024 → 029 → входы TabPFN.
Поиск параметров не повторяется. Runtime и активная версия не переключаются.
Один запуск — отдельный процесс и новый каталог; существующий результат не перезаписывается.

`--history-end` — последняя календарная дата фактов включительно. Например,
`2025-11-30` даёт период `[2025-12-01, 2026-01-31)`: декабрь и первые 30 дней января,
ровно 61 сутки. Собственные прогнозы не становятся историей.

## Окружение

Python 3.12, Linux с NVIDIA CUDA для новых TimesFM-вычислений:

```sh
python3 -m venv ml/.venv-prepare
ml/.venv-prepare/bin/python -m pip install -r ml/preparation/requirements.txt
make prepare-ml-model PYTHON="$PWD/ml/.venv-prepare/bin/python"
```

TimesFM устанавливается отдельно один раз; закреплены ревизия и SHA256 весов:

```sh
ml/.venv-prepare/bin/python -c 'from huggingface_hub import hf_hub_download; hf_hub_download("google/timesfm-2.5-200m-pytorch", "model.safetensors", revision="1d952420fba87f3c6dee4f240de0f1a0fbc790e3", local_dir="ml/models/timesfm")'
```

SHA256 `model.safetensors`:
`2f776efe6245e42b24bc4153ffdf61810140210e4bd3b01fb21f7aa779ab6ce8`.
Сам builder ничего не скачивает. Скорость и память всей подготовки на RTX 3070
не измерены; измерения runtime 030 не относятся к этому процессу.

## Источники для нового периода

Создать отдельный комплект редактируемых снимков без копирования старых прогнозов:

```sh
ml/.venv-prepare/bin/python ml/preparation/build.py --init-sources ml/sources/next
```

Обновить в нём:

| Путь относительно `ml/sources/next` | Требование |
|---|---|
| `artifacts/calendar_sources.json` | Полное покрытие истории и будущего. Для нескольких лет: `{"calendars": [<прежний объект>, <объект нового года>]}`. Каждый объект содержит `coverage`, `known_at`, `holidays`, `transfers`, `working_weekends`; периоды не пересекаются |
| `artifacts/portfolio_20260926/continuation/external/weather_2025.csv` | Сохраняется историческое имя файла, но даты продолжаются до конца нового горизонта. Обязательны `date;temperature_2m_mean;precipitation_sum;daylight_duration` |
| Там же `weather_source.json` | `sha256` нового CSV, `url`, `retrieved_at`, `regime` с описанием: наблюдения, прогноз или сценарий. Старый формат SHA исходного API JSON также поддерживается с проверкой равенства производной таблицы |
| Там же `school_calendar/sources.json` | Покрытие, интервалы каникул и происхождение с датами доступности. Смена одной `coverage` без проверки интервалов не обновляет календарь |
| Там же `movement_calendar.json` | Проверенное покрытие и датированные события. Существующие категории ограничены правилами маршрутов 7/50 и 17; новые виды изменений требуют развития модели. Не продлевать старые ограничения автоматически |

Снимки прошлых дат сохраняются: они нужны для повторного расчёта прошлых ошибок.
Если новый производственный календарь ещё не был известен в исторической точке,
соответствующая проверка останавливает расчёт. Школьные признаки используют только
известные на ту дату интервалы. Погода допускает явно описанный ретроспективный режим;
для реального будущего нужны прогноз погоды или сценарий, а не выдуманные факты.
Файлы `selection.json` — фиксированные настройки выбранного семейства, не результаты нового поиска.

## Запуск

Из исходных экспортов плюс новый месяц:

```sh
ml/.venv-prepare/bin/python ml/preparation/build.py \
  --events dataset/train.csv dataset/test.csv dataset/2025-11.csv \
  --no-labels --history-end 2025-11-30 \
  --sources ml/sources/next \
  --timesfm-model ml/models/timesfm/model.safetensors \
  --output ml/releases/history-2025-11-30
```

Входные CSV имеют исходную схему событий. `--no-labels` явно отключает сверку
с labels, если новых labels нет; это записывается в аудит. При наличии полного
обновлённого комплекта `train.csv`, `test.csv`, `labels/` используется
`--dataset /path/to/dataset` без этого флага.

Повторно использовать уже агрегированную историю можно через
`--history /path/to/hourly_clean.csv` вместо `--events`/`--dataset`. Требуются
полная сетка с 01.01.2025 по `--history-end`, целые счётчики `boardings`,
`working_events` и согласованная маска `working_events_observed`.
Оценки восстановленных пропусков не подставляются в неё как наблюдения.

Make-обёртка: `make prepare-ml-data PYTHON=<python> ML_PREPARE_ARGS="<те же аргументы>"`.
Запускать после получения нового согласованного комплекта данных. Периодический
планировщик и автоматическая загрузка источников не добавлены.

Входы хешируются; изменение raw во время чтения останавливает выпуск.
Совпадающие события на общей граничной дате отклоняются. Перекрывающиеся на
несколько дней экспорты нужно заранее разделить; внутрифайловая полная дедупликация
не реализована. Нули заполнения и маски наблюдаемости сохраняют прежний смысл.

## Результат и включение

Каталог результата содержит `base.csv`, `inputs.npz`, `recipe.json`, `sources.json`,
`build.json`, лицензию и `preparation/` с агрегатами, исходниками и промежуточными
расчётами. Raw и веса туда не копируются. `recipe.json` ссылается на абсолютный путь
установленного TabPFN checkpoint; при переносе пакета путь нужно согласовать с хостом.

Публикация каталога выполняется после проверки точной сетки, чисел и размерностей
runtime-загрузчиком. Ошибка не создаёт готового пакета и не затрагивает прежний.
`dataset_version` учитывает манифест всех источников вместе с подготовленными входами.

Дальше отдельно выполнить `service.py --config <новый recipe.json> --describe`,
прогреть кэш через `--warm-cache` и запустить сервис с этим конфигом или `ML_CONFIG`.
Для Compose каталог релиза и веса должны быть доступны внутри контейнера по путям
конфига. Затем зарегистрировать согласованную версию в Go, когда интеграция готова.
Сам builder не вызывает финальный TabPFN, не публикует точки в PostgreSQL и не
утверждает улучшение качества. Метаданные содержат `quality_evaluated: false`.

## Проверка и ограничения

Быстрые проверки: `make test-ml-preparation PYTHON=<python>`.
Сквозная синтетическая проверка переноса месяца:
`<python> ml/preparation/test_rolling.py`. В ней TimesFM заменён явно обозначенным
тестовым вычислителем; TabPFN не вызывается, но установленный checkpoint нужен
для проверки пакета. Она проверяет цепочку и контракт, а не реальные прогнозы или качество.

Для повторной сборки исходного периода без GPU можно передать
`--timesfm-cache ml/lab/artifacts/portfolio_20260926/continuation/timesfm_teachers/quantiles`.
Повторное использование разрешено только при совпадении матрицы входов, периода,
параметров, версии весов и хешей файлов. Несовпадение требует `--timesfm-model`.
Старые 029 и дневные прогнозы не подхватываются из исследовательского кэша.

Проверенная локальная среда пересборки: NumPy 2.3.5, pandas 2.2.3, scikit-learn 1.9.1.
Сборки из исходной почасовой истории и из всех 62 443 497 raw-событий прошли все
этапы, используя проверенные TimesFM-квантили. При подготовке из raw нет расхождений
с labels до очистки; SHA256 очищенной истории совпал с исходным снимком.
Обе независимые сборки дали одинаковые числовые массивы и базу.
База отличается от архивной 029 примерно на 0,95% relative L1.
Среда отличается от исторической, поэтому битовое совпадение не заявляется;
это новый комплект, а не воспроизведение официального score старой посылки.

Модель сохраняет 61-дневный горизонт и историю с января 2025. Добавление нового
месяца технически поддержано; качество, сезонная применимость и параметры по-прежнему
нуждаются в оценке на реальных новых фактах. Годовой горизонт, инкрементальное
обучение и автоматический выбор лучшей модели сюда не входят.
