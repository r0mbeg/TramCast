# Эксперимент: ограниченная поправка к baseline

**Результат: вариант отклонён, опорным остаётся сезонный baseline.** Поправка ухудшила оба окна относительно baseline.

| WAPE-score | Июль–август | Сентябрь–октябрь | Среднее |
| --- | ---: | ---: | ---: |
| Baseline: среднее всей истории | 0,77915 | 0,86243 | **0,82079** |
| Первая ML с календарём | 0,83063 | 0,72216 | 0,77640 |
| ML без абсолютного календаря | 0,77384 | 0,79454 | 0,78419 |
| ML-поправка к baseline, ±20% | 0,71931 | 0,81657 | 0,76794 |

Разница с baseline: **−0,05984** летом, **−0,04586** осенью, **−0,05285** в среднем. В сравнении с предыдущей ML без календаря осень улучшилась, но лето ухудшилось сильнее. Это не основание выбирать новый вариант.

## Постановка до запуска

База `b` — среднее профиля `маршрут × день недели × час` по всей истории до соответствующей точки прогноза, до округления. Цель модели изменена с абсолютного количества посадок на остаток `y − b`. В обучении используется полный остаток, без обрезки. При прогнозе:

```text
prediction = round_half_up(max(0, b + clip(predicted_residual, −0.2*b, +0.2*b)))
```

Предел ±20% задан до получения результата, не подбирался. Он действует до округления. Если `b = 0`, результат равен нулю; маршрут 5 и часы 01–04 обнуляются общей постобработкой независимо от поправки.

Признаки, параметры бустинга, seed 42, обучающие точки и разбиения сохранены как в предыдущем эксперименте без абсолютного календаря. Это проверка совместного изменения цели и ограниченного восстановления прогноза, а не отдельная оценка влияния только остаточной цели или только ограничения. Совпадение параметров, признаков, числа обучающих строк, точек прогноза и SHA-256 исходной таблицы проверено по метаданным.

## Что видно по ошибкам

Суммарный летний прогноз завышен на **23,59%**, осенний занижен на **10,93%**. Ограничение на каждую поправку не означает ограничения общей ошибки относительно факта: сам baseline тоже ошибается. Осеннее суммарное смещение стало меньше, чем у предыдущей ML без календаря (−14,25%), однако WAPE всё ещё хуже baseline. Смещение и абсолютная ошибка оценивают разные свойства прогноза.

Наблюдения не подтверждают гипотезу, что переход к ограниченной поправке сам по себе даст устойчивое улучшение. Модель может выучить неверное направление изменения спроса даже при небольших поправках. Конкретная причина требует отдельной проверки; нельзя считать её установленной только по этим двум окнам.

Перед следующей модельной вариацией полезнее разобрать обучающие точки и распределение остатков по времени/маршрутам: совпадает ли направление выученных изменений с летним и осенним режимами. Такой разбор ещё не выполнен. Гиперпараметры по текущим результатам не менялись. Итоговая модель для ноября–декабря не обучалась, submission не создавался.

## Воспроизведение

```sh
python test_pipeline.py
python test_model.py
python model.py --residual-correction
```

Флаг подразумевает исключение абсолютного календаря. Обычный запуск и `--no-absolute-calendar` воспроизводят прежние варианты. Старые артефакты сохранены.

Новые файлы: `ml_residual_metrics.csv`, `ml_residual_breakdown.csv`, `ml_residual_predictions.csv`, `ml_residual_run.json`, локальные модели `model_residual_2025-06-30.pkl` и `model_residual_2025-08-31.pkl`. Предел поправки сохраняется внутри модели и в метаданных, поэтому восстановленный из файла прогноз использует то же правило.

Два окна заняли **7,23 с**, пиковая память **240,6 MiB**, четыре вычислительных потока. Это пакетный эксперимент, не замер API. Проверены: отсутствие утечки, обе полные сетки, совпадение сохранённых метрик, обязательные нули, целочисленные прогнозы и предел поправки на каждом ключе. Тест нулевой поправки точно воспроизводит baseline; отдельные проверки больших положительных/отрицательных остатков подтверждают ограничение, а нулевая база остаётся нулевой. Сохранение и загрузка модели не меняют прогноз.
