# Эксперимент: убрать абсолютные календарные признаки

**Результат: baseline остаётся опорным подходом.** Удаление трёх признаков улучшило осень, но ухудшило лето; новая ML-конфигурация уступает среднему всей истории на обоих окнах.

| WAPE-score | Июль–август | Сентябрь–октябрь | Среднее окон |
| --- | ---: | ---: | ---: |
| Baseline: среднее всей истории | 0,77915 | **0,86243** | **0,82079** |
| Первая ML-модель | **0,83063** | 0,72216 | 0,77640 |
| ML без абсолютного календаря | 0,77384 | 0,79454 | 0,78419 |
| Изменение относительно первой ML | −0,05680 | +0,07237 | +0,00779 |

Лучшие ранее подобранные сезонные варианты по отдельным окнам дают 0,81765 летом и 0,87945 осенью; это не единая конфигурация.

## Условия сравнения

Единственное изменение входа модели: удалены `month`, `day_of_year`, `origin_day_of_year`. Остались маршрут, час, день недели, горизонт, среднее исторического профиля за всю историю, среднее и медиана за 28 дней. День недели сохранён, поэтому это не эксперимент «без любого календаря».

Параметры бустинга, seed 42, обучающие точки, строки цели, cutoff, горизонт и постобработка не менялись. Совпадение параметров, SHA-256 исходной таблицы, числа примеров и точек обучения проверено по метаданным двух запусков. Исходные ML-артефакты сохранены, новые записаны отдельно. При инференсе берётся именно схема признаков обученной модели.

## Вывод

Осенняя недооценка суммарного потока сократилась с **23,97% до 14,25%**, но летнее завышение выросло с **4,38% до 16,28%**. Средний score улучшился лишь на **0,00779** и остаётся на **0,03660** ниже baseline.

Эксперимент подтверждает влияние удалённого блока на поведение модели: осеннее ухудшение частично уменьшается при его удалении. Он не доказывает, что вся проблема вызвана календарём, и не позволяет разделить вклад каждого из трёх признаков. Гипотеза «достаточно убрать абсолютный календарь» не подтвердилась. Два окна уже используются для разработки; результаты не являются независимой оценкой скрытого ноября–декабря.

Следующая возможная гипотеза: учить ограниченную поправку к устойчивому сезонному baseline вместо абсолютного числа посадок. Это отдельный будущий эксперимент; в этом запуске не реализован. Простое удаление признаков не принято как новая итоговая модель.

## Воспроизведение

```sh
python test_pipeline.py
python test_model.py
python model.py --no-absolute-calendar
```

Обычный `python model.py` по-прежнему воспроизводит исходную модель. Зависимости не изменены. Результаты:

- `ml_no_calendar_metrics.csv` — общая оценка и сравнение с baseline.
- `ml_no_calendar_breakdown.csv` — ошибки по маршрутам, часам и месяцам.
- `ml_no_calendar_predictions.csv` — прогнозы и факты обоих окон.
- `ml_no_calendar_run.json` — точные признаки, параметры, входной хеш и ресурсы.
- `model_no_calendar_2025-06-30.pkl`, `model_no_calendar_2025-08-31.pkl` — локальные модели окон, исключены из Git.

Два окна заняли **7,11 с**, пик памяти **231,5 MiB**, четыре вычислительных потока. Проверены изоляция будущих фактов, схема признаков обеих конфигураций, полные выходные сетки, целочисленные неотрицательные прогнозы, нули маршрута 5/часов 01–04, совпадение метрик с сохранёнными прогнозами и неизменность результата после сохранения/загрузки модели.
