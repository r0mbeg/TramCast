# Первая табличная модель: сравнение с baseline

**Решение: сохранить сезонный baseline как опорный подход.** Первая фиксированная ML-конфигурация улучшает лето, но существенно ухудшает осень. Итоговую модель на ноябрь–декабрь из этого эксперимента не обучали и submission не заменяли.

## Результат

Метрика — WAPE-score на той же очищенной полной сетке, с теми же нулями и округлением.

| Модель | Июль–август | Сентябрь–октябрь | Среднее двух окон |
| --- | ---: | ---: | ---: |
| Опорный baseline: среднее всей истории | 0,77915 | **0,86243** | **0,82079** |
| ML: градиентный бустинг | **0,83063** | 0,72216 | 0,77640 |
| ML минус baseline | +0,05148 | −0,14027 | −0,04439 |

Для полноты: лучший из ранее проверенных baseline на летнем окне — среднее четырёх недель, 0,81765; на осеннем — медиана всей истории, 0,87945. ML превосходит даже лучший летний baseline примерно на 0,013, но не даёт устойчивого выигрыша. Выбор разных baseline задним числом для каждого окна не является одной моделью. Оба окна уже используются для разработки; это не независимый финальный тест.

## Что проверено

Одна общая модель для девяти непустых маршрутов: `HistGradientBoostingRegressor` из scikit-learn. Функция потерь — абсолютная ошибка, соответствующая числителю WAPE. Фиксированные параметры: 150 итераций, learning rate 0,08, максимум 15 листьев, минимум 50 примеров в листе, L2 = 1, seed = 42. Ранняя остановка отключена, подбора параметров по этим двум окнам не было. Маршрут и день недели заданы категориальными признаками. [Документация модели](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.HistGradientBoostingRegressor.html).

Признаки: маршрут, час, день недели, месяц, день года, горизонт 1–62 суток, день года точки прогноза, среднее профиля `маршрут × день недели × час` по всей доступной истории, среднее и медиана того же профиля за последние 28 дней. Праздники, погода и иные внешние данные не добавлялись. Маски наблюдений и фактические значения будущего в признаки не включаются.

Обучение имитирует пакетный прогноз: исторические точки через каждые 28 дней, для каждой признаки фиксируются по истории до этой точки, цель — следующие 62 дня. Включаются только полностью известные горизонты до внешнего cutoff. Поэтому одно событие может быть обучающей целью для нескольких точек с разным горизонтом; это не независимые наблюдения. Модель обучается на 44 640 примерах для летнего окна и 66 960 для осеннего. Список точек сохранён в `ml_run.json`.

Фактические периоды проверки имеют 62 дня (июль–август) и 61 день (сентябрь–октябрь). Для каждого выполняется прямой прогноз всех часов без обновления истории внутри периода. Маршрут 5 и часы 01–04 исключены из обучения и получают нули в ответе; час 05 обучается на очищенной половине часа.

## Ошибки и ограничение подхода

Летом суммарное смещение составляет **+4,38%**, осенью — **−23,97%**. Осеннее ухудшение наблюдается у всех девяти непустых маршрутов. Наибольший прирост абсолютной ошибки относительно среднего всей истории: маршрут 7 — около 306 тыс. посадок, маршрут 17 — 274 тыс., маршрут 12 — 239 тыс.

По месяцам score ML: июль 0,81559, август 0,84595, сентябрь 0,73756, октябрь 0,70783. Поэтому ошибка не сводится к отдельному аномальному дню маршрута 50.

**Гипотеза, не установленная причина:** календарные признаки и недавние профили могли перенести летний спад на осень, которой модель ещё не видела. Истории для повторного наблюдения годовой сезонности нет. Чтобы проверить гипотезу, следующий ограниченный эксперимент — убрать абсолютные календарные признаки (`month`, `day_of_year`, `origin_day_of_year`), сохранив все остальные условия. До такого сравнения не приписывать падение качества конкретному признаку. Не добавлять ручную осеннюю поправку, вычисленную из фактов валидации.

## Воспроизведение и артефакты

```sh
python -m pip install -r requirements.txt
python test_pipeline.py
python test_model.py
python model.py
```

Нужны подготовленные `artifacts/hourly_clean.csv` и `artifacts/baseline_metrics.csv`. Скрипт не перечитывает сырые 10 GiB.

- `ml_metrics.csv` — сравнение с опорным baseline и смещение.
- `ml_breakdown.csv` — ошибки по маршрутам, часам и месяцам.
- `ml_predictions.csv` — все почасовые прогнозы и факты обоих окон.
- `ml_run.json` — параметры, схема признаков, точки обучения, версии, SHA-256 очищенной истории и измеренные ресурсы.
- `model_2025-06-30.pkl`, `model_2025-08-31.pkl` — локальные модели окон, исключены из Git. Это исследовательские артефакты; для инференса также нужны код признаков и история до соответствующего cutoff. Загрузка собственных сохранённых моделей проверена на точное совпадение прогнозов.

Текущий запуск: Python 3.12.14, pandas 2.2.3, numpy 2.3.5, scikit-learn 1.9.1. Два окна вместе заняли **7,23 с**, пиковая память **238,9 MiB**, ограничение — четыре вычислительных потока. Время включает сбор признаков, обучение, оценку и проверку сохранённых моделей, но не установку зависимостей. Это не нагрузочный тест API.

Проверки прошли: изменение фактов после cutoff не меняет ни обучающие примеры, ни прогнозные признаки; каждый исторический профиль использует только данные до собственной точки прогноза; маршрут 5/нерабочие часы не попадают в обучение; выход — неотрицательные целые числа с обязательными нулями. Общая постобработка переиспользуется baseline и ML.
