# Очищенная разметка и сезонный baseline

## Подготовка

Полностью обработаны **62 443 497** строк двух сырых CSV (около 9,68 GiB). До фильтра рабочего времени агрегаты в точности совпали с исходными labels по всем ключам полной сетки: **0 расхождений**, **59 667 191** успешная валидация.

- Исключено **2 775 691** неуспешное событие в разрешённом периоде.
- Исключено **615** записей ноября за границей истории независимо от результата оплаты.
- Из успешных событий удалено **122 051** вне рабочего времени, **0,205%** исходной цели.
- Осталось **59 545 140** посадок. Сохранена сетка **72 960** строк за январь–октябрь по 10 маршрутам, включая нули маршрута 5 и нерабочих часов.

| Исключённое время | Число успешных событий |
| --- | ---: |
| 01:00–01:59 | 14 948 |
| 02:00–02:59 | 575 |
| 03:00–03:59 | 653 |
| 04:00–04:59 | 12 823 |
| 05:00–05:29 | 93 052 |

**76,2% удалённых событий находятся в первой половине пятого часа.** Простое обнуление часов 01–04 не заменяет пересборку цели из сырых timestamps. Часы 00 и 05:30–05:59 сохранены по принятой трактовке Q&A.

## Граница файлов

В `train.csv` есть **550 событий 1 сентября**, из них **523 успешных**. Они входят в сентябрьские labels, но не повторяются в `test.csv` по проверенной комбинации `tran_no, device_no, tran_date_time, ngpt_route, validation_result`. После очистки из этого хвоста сохраняется **468** посадок в часе 00.

Поэтому обе части объединяются по timestamp: сентябрьский хвост включается в сентябрьскую историю, а затем временное разбиение выполняется по дате. Привязка выборки к имени сырого файла теряет эти события. Среди событий 1 сентября в `test.csv` 163 784 повторных значения `tran_no`: он не является глобально уникальным ключом. Произвольная дедупликация не выполнялась. Сверка агрегатов не является доказательством отсутствия любых дубликатов в сырых данных.

## Оставшаяся неопределённость покрытия

Для девяти непустых маршрутов есть **54 720** рабочих сочетаний маршрут–дата–час. В **732** нет успешных рабочих событий; в **730** нет даже неуспешных рабочих событий. Это не означает автоматически нулевой спрос: причина отсутствия данных неизвестна. Они приняты за ноль для baseline с сохранением масок наблюдений; модельного восстановления пока нет.

У маршрута 50 на **21.09.2025** нет рабочих событий вообще — провал подтверждён сырым файлом, а не только labels. Это всё ещё не позволяет различить остановку движения и отсутствие данных.

## Валидация

Профиль `маршрут × день недели × час`; прогноз сразу на весь период после cutoff, без использования будущих фактов. Полная сетка, неотрицательное целочисленное округление, нули маршрута 5 и часов 01–04.

| Профиль | Июль–август, cutoff 30 июня | Сентябрь–октябрь, cutoff 31 августа |
| --- | ---: | ---: |
| Среднее последних 4 недель | **0,81765** | 0,79033 |
| Медиана последних 4 недель | 0,81495 | 0,79355 |
| Среднее всей истории | 0,77915 | 0,86243 |
| Медиана всей истории | 0,74645 | **0,87945** |

Это WAPE-score на очищенной цели. Тот же осенний прогноз медианы всей истории при сравнении с исходными labels получает **0,87854**. Его прежняя оценка **0,87934** относилась к необработанным данным и дробным прогнозам: сравнение этих чисел не является доказательством улучшения модели. Скрытая разметка ноября–декабря недоступна.

Проверены 16 сочетаний периода, окна и статистики; полные результаты — `baseline_metrics.csv`, детализация по маршрутам/часам/месяцам — `baseline_breakdown.csv`. Ни одно окно не выигрывает на обоих периодах. По среднему score двух окон лучшая единая конфигурация — **среднее всей доступной истории: 0,82079** (медиана всей истории — 0,81295; среднее последних четырёх недель — 0,80399). Её можно использовать как общую опорную конфигурацию, но это выбор по использованной валидации, не независимая оценка. Лучший осенний вариант сохраняется как отдельная точка сравнения. Итоговая конкурсная модель и submission на этом шаге не выбирались.

## Воспроизводимость и проверки

Команды приведены в корневом README. Текущий запуск: Python 3.12.14, pandas 2.2.3, numpy 2.3.5. Случайности нет. Размеры и времена изменения входных файлов записаны в `preparation_audit.json`.

На текущей машине подготовка заняла **126,1 с**, пиковая память процесса **959,7 MiB**; оценка 16 вариантов — **42,7 с**, **118,7 MiB**. Это время успешного запуска, без предыдущего диагностического прохода. Замеры относятся к пакетной обработке, а не к будущему API.

Проверки выполнены: временные границы 00:59/01:00/05:29/05:30, фильтр результата оплаты, перенос сентябрьского хвоста по дате и исключение ноября, нули маршрута 5, округление x,5, формула WAPE и отсутствие влияния будущей цели на профиль. Дополнительно проверены полная сетка и точное совпадение исходных агрегатов с labels.

Следующий эксперимент: сравнить baseline с одной общей табличной ML-моделью на тех же окнах, уделив внимание сменам режима маршрутов 7 и 50. Не скрывать пропуски восстановленной «истиной» при оценке.
