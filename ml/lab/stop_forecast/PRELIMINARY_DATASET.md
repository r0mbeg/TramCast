# Предварительный московский датасет D20260927-v1

Собран из локальной книги, проверенного маршрутного ledger и ранее скачанной
интернет-статистики метро. Это **датасет признаков и маршрутных наблюдений**;
остановочных обучающих меток в нём нет. Нужен для подготовки признаков,
проверки связей и следующих сценарных/агрегатных моделей, не для утверждения
остановочной точности BL–FS. Ничего не опубликовано и не импортировано в сервис.

| route_hours.csv.gz | 29 184 | Четыре маршрута × 304 дня × 24 часа, январь–октябрь 2025; реальные маршрутные счётчики, статусы и непривязанный остаток |

| metro_links.csv | 66 | Все кандидаты связи остановочной позиции с записью метро за последний завершённый квартал |

49 позиций имеют явное название вида `Метро "…"`. Для 32 найден один
кандидат станция–линия, для 17 — несколько. Нормализация ограничена регистром,
пробелами, Unicode и ё/е; нечёткое сопоставление не применяется.
**Даже единственный кандидат не доказывает наличие удобной пересадки**:
пешеходная доступность, входы метро и исторические изменения не проверены.
Остальные 266 позиций не имеют такой явной ссылки; это не означает отсутствия
метро поблизости. Доля подтверждённых пространственных связей пока неизвестна.

`IncomingPassengers` и `OutgoingPassengers` в stop_features — квартальные
счётчики метро только для единственного кандидата. Для неоднозначных и
отсутствующих кандидатов поля пусты. Потоки разных линий не складываются,
не делятся на часы и не трактуются как посадки в трамвай. Нули метро отмечены
для дополнительной проверки; они могут отражать особенности учёта входов.
`pilot_catalog_routes_at_stop` считает маршруты только в этих четырёх схемах,
а не все городские пересадки. Повторные вхождения сохранены отдельно.

для строгой имитации реального прогноза нужны даты публикации и историческая сеть.

## Как использовать

Таблицы оставлены раздельными, чтобы не размножать один маршрутный факт по
остановкам. Позиционный ключ — occurrence_id (номер маршрута, trip_id,
stop_sequence в пространстве workbook), отдельно сохранены направление,
stop_id и network_version. Маршрутный ключ — route/date/hour. Для модели
обучения по агрегатам позиции одной группы route/date/hour образуют набор,
которому соответствует **одна** маршрутная цель. Присваивать её каждой
остановке в качестве stop label нельзя. stop_observed_boardings всюду пусто.

Для первого пилота фильтровать route=12: 97 позиций; обучение остановочной
BL–FS пока невозможно. Можно проверить дополнительные ковариаты в агрегатной
модели и чувствительность сценариев к ним. Улучшение маршрутной ошибки не
будет доказательством улучшения остановочных долей.

Исторические окна следует готовить отдельно с соответствующим cutoff: нельзя
брать сентябрьскую статистику метро для майского прогноза. Скрипт позволяет
задать cutoff и использует только завершённые кварталы; неизвестная дата
публикации и поздняя география остаются ограничениями при любом cutoff.

```sh
.venv/bin/python ml/lab/stop_forecast/build_preliminary.py --cutoff 2025-10-31 --out /tmp/tramcast-preliminary-new
.venv/bin/python -m unittest discover -s ml/lab/stop_forecast
```

Выход должен быть новым; исходники и прежние результаты не перезаписываются.
Генератор проверяет входную контрольную сумму метро, квартальные ключи,
маршрутные ключи, уникальность позиций и отсутствие подмены пропусков метками.
Дополнительно на сохранённом наборе проверены все хеши, отсечение IV квартала,
пустые значения у неоднозначных кандидатов и баланс непривязанных событий.
Unit-тест проверяет правила имён, нулевые счётчики и временное отсечение.
CSV остаются локально; код, сводка, manifest и описание воспроизводимы.

## Следующее обогащение

1. Исторические входы метро и пешеходные связи: заменить кандидатов по имени
   проверенными расстояниями/временем доступа, сохраняя неоднозначности.
2. Исторические схемы трамвая и обслуживание по направлениям; расписание
   отдельно от фактически выполненных рейсов.
3. Население, рабочие места и объекты притяжения с датой снимка и покрытием;
   не объявлять число POI фактическим пассажиропотоком.
4. Подтверждённые остановочные валидации и полнота регистрации для обучения
   и независимой оценки BL–FS. Без этого набор остаётся предварительным.
