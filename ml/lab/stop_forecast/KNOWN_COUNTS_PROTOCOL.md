# K20260927-v1: обучение на проверяемых счётчиках

Зафиксировано до подготовки нового набора и измерения результатов. Пользователь
просит построить датасет для предсказания величин, точно присутствующих в raw.
Первый опыт — маршрут 12 × дата × 15-минутный интервал; это временная
детализация успешных валидаций, **не остановки, направления или загрузка**.

## Данные и проверка

Январь–октябрь 2025, неизменные train/test из аудита S-v2. Перечитать три
поля: tran_date_time, ngpt_route, validation_result. Переиспользовать рабочее
окно pipeline.aggregate/working_time: [00:00,01:00) и [05:30,24:00).
Не дедуплицировать по картам; счётчик означает зарегистрированные события,
не полноту всех оплат. Для каждой четверти часа сохранить число успехов,
число всех рабочих событий, observed_counter (null при отсутствии событий),
статус наблюдения и число рабочих минут. Ночные/ранние четверти — структурные
нули. Наличие событий не доказывает полную исправность всех валидаторов.

Проверить SHA256 обоих raw по S-v2 и баланс всех 7296 маршрутных часов:
сумма четырёх четвертей равна прежним boardings и working_events. Сохранить
происхождение и хеши; никакие остановочные псевдометки не создавать.

## Разбиение, кандидаты и бюджет

Окна: cutoff 30.04 → 01.05–30.06; 30.06 → 01.07–30.08;
31.08 → 01.09–31.10. Ровно 61 день, никаких обновлений фактами внутри окна.
Эти периоды уже просмотрены в других исследованиях: это исторический backtest,
не новый независимый тест. 31 августа входит в историю третьего окна.
Отдельный финальный прогноз: cutoff 31.10 → 01.11–31.12, фактов для оценки нет.

Все новые модели используют последние 56 календарных дней до cutoff и только
часы, где каждая рабочая четверть имеет хотя бы одно событие любого результата.
Календарь — день недели и выходной (сб/вс), без производственных переносов.
На первом окне выбрать минимум WAPE 15-минутных счётчиков из пяти кандидатов,
при точном равенстве предпочесть первый по списку; затем выбор заморозить:

1. 030 × равные доли рабочих четвертей (в часе 5 только две).
2. 030 × исторические доли по часу.
3. 030 × исторические доли по часу и типу дня.
4. 030 × Dirichlet posterior mean долей по часу и дню недели.
5. Прямая средняя по дню недели × часу × четверти за те же 56 дней.

Для 2 и 3 pooled multinomial counts; при пустом знаменателе fallback
часовой профиль, затем равномерный. Для 4 prior mean — часовой профиль
(к счётчикам добавляется один псевдослучай равномерно по рабочим четвертям).
Концентрация prior равна семи средним часовым счётчикам данного часа,
минимум 1. Это empirical Bayes, оценка prior только из train, без перебора
силы штрафа; posterior (n_q + alpha*p_q)/(N + alpha).
Предположение multinomial упрощает неоднородность дней; доверительные интервалы
не выпускать. Для 5 при отсутствии weekday fallback средний профиль часа.

030 — сохранённый контроль, его не переобучать и не менять. Его исторический
выбор/ретроспективные внешние признаки наследуются, «всё доступно на cutoff»
для него не утверждать. Новым долям достаточно календаря и истории до cutoff.
Бюджет: один проход raw, пять фиксированных кандидатов, три окна, один финальный
выпуск; CPU, без GPU, новых зависимостей и поиска гиперпараметров.

## Метрики и контроль утечки

Основной общий срез — рабочие четверти часов с наблюдениями во всех рабочих
четвертях. Дополнительно оценить все отдельные наблюдаемые рабочие четверти,
показать покрытие часов/четвертей и долю событий основного среза. Структурные
нули не улучшают основную метрику. Нет событий — null, не обучающий ноль.

WAPE/MAE после целочисленного согласования: largest remainder до half-up
округлённого маршрутного часа 030; прямой прогноз округляется по четвертям.
Отдельно почасовая ошибка, срезы по часу, типу дня и дальности 1–14/15–35/36–61.
Для моделей долей отдельно диагностировать распределение с **фактической**
часовой суммой (oracle): это не прогноз, не вход обучения и не критерий выбора.
Сохранить предсказания всех моделей и frozen выбор. Тесты проверяют границу
05:30, ноль/пропуск, баланс округления, нормировку долей и неизменность
обученных параметров при изменении будущих целевых значений.

При хорошем результате доказана предсказуемость временных счётчиков; перенос
этого результата на географические остановки запрещён. При отрицательном
результате сохранить его. Финальный выпуск только локальный исследовательский,
без интеграции, публикации или конкурсной отправки.
