# Отдельный BL–FS и энтропийная регуляризация

Реализована адаптация независимого BL–FS с фиксированными коэффициентами и KL-штрафом. **На московских остановках модель
не обучена: реальных полных остановочных наблюдений нет.** Отдельно выполнено
сценарное применение энтропийной регуляризации к прежним интенсивностям.
Эти два результата нельзя смешивать. Основной запуск —
[F20260927-v2](runs/shares-20260927-v2/results.json),
[контрольные суммы](runs/shares-20260927-v2/manifest.json).

## Соответствие статье

[статья](https://www.sciencedirect.com/science/article/pii/S0965856420306340),
[авторский PDF](https://people.cecs.ucf.edu/neluru/wp-content/uploads/2022/04/Route-paper.pdf).
27.09.2026 изучены разделы издателя и индексированные фрагменты авторского
текста с формулами; прямое открытие PDF не удалось. Авторы сравнивают независимый
BL–FS с совместной панельной моделью: бинарная часть описывает ненулевой поток,
multinomial fractional split — доли. Реализован **независимый базовый вариант**.
Связанные случайные эффекты и панельная корреляция из основной модели статьи
не реализованы. Коэффициенты Орландо не переносились; точного воспроизведения
авторского эксперимента не заявляем. KL-штраф — наше расширение.

## Реализация обучения

[fractional_split.py](fractional_split.py), функции `fit` и `predict`:

- BL: `a_i=sigmoid(alpha_0+x_i alpha)`, бинарный ответ `1[y_i>0]`.
- FS: `p_i=softmax(x_i beta)` среди остановок с наблюдаемым положительным
  счётчиком. Цель — фактическая доля `y_i/sum(y)` в маршрутном периоде.
- Функция потерь: средний binary cross-entropy по строкам + средний fractional
  cross-entropy по положительным маршрутным периодам +
  `lambda * mean_group sum_i p_i log(p_i/q_i)` + L2 с коэффициентом 0.01.
  При равномерном `q` KL равен `log(n)-H(p)`, то есть штраф поощряет энтропию.
  `q` ограничивается и нормируется на том же положительном наборе.
- Полностью нулевая группа участвует только в BL; деления на ноль в FS нет.
- Прогноз: порог BL 0.5 задаёт набор остановок, FS нормируется внутри него.
  Если набор пуст, вся маршрутная сумма остаётся `unassigned`. Это явная
  прикладная адаптация, не интегрирование случайного набора положительных
  остановок и не утверждение о калибровке вероятностей.

`fit(x, edges, y, q, observation_status=..., evidence_ref=..., route_totals=...,
expected_sizes=..., strength=...)` принимает числовые признаки, границы групп
и реальные целые счётчики. Требуются статус `observed_complete`, непустая
ссылка происхождения каждой строки, ожидаемое число позиций и точный баланс
с маршрутным счётчиком. `missing`, `observed_partial`,
`observed_unknown_completeness` и `restored_estimate` отвергаются. Полноту
и действительность свидетельств должен проверить подготовитель данных;
программная проверка строк не доказывает их происхождение.

Группы — маршрут×дата×час, внутри них отдельные направления/варианты/вхождения.
Матрица признаков должна быть подготовлена по обучающему периоду; интерфейс
не делает автоматического разделения времени или проверки смысла признаков.
Результат `fit` содержит коэффициенты и диагностику, `predict` — вероятность
ненулевого потока, долю, ожидание посадок и нераспределённый остаток.
Это библиотечный интерфейс ML-полигона, не контракт Go и не runtime 030.

## Что реально запущено на Москве

Супервизируемый `fit` не вызывался на маршрутных суммах или искусственных
остановочных метках. Вместо этого выполнена отдельная **сценарная проекция**:

```
min_p KL(p || s) + lambda KL(p || q),  sum(p)=1
p_i ∝ exp((log(s_i) + lambda log(q_i)) / (1 + lambda))
```

`s` — неподтверждённые доли из сохранённой модели интенсивностей B20260927-v4.
Они используются как исходное распределение, а не как остановочный эталон.
Это другая задача, чем обучение BL–FS выше; она не даёт обученных коэффициентов
BL/FS и не подтверждает правильность `s`. Приняты все позиции позднего снимка,
вероятности ненулевого потока отсутствуют. `q` — равномерный prior либо явно
гипотетический prior `exp(-0.5 * standardized_distance_to_centre)`.
Ни один из них не подтверждён московскими наблюдениями.

Проверены пять сил штрафа на четырёх неизменённых временных точках прежнего
опыта. Ни новые цели внутри 61-дневных горизонтов, ни Коломна не использовались.
Итоговые диагностики по 160 контекстам четырёх маршрутов, prior равномерный:

| lambda | Средняя H/log(n) | Средний KL к prior | TV относительно исходных долей |
|---:|---:|---:|---:|
| 0 | 0.6970 | 1.3058 | 0% |
| 0.1 | 0.7385 | 1.1255 | 4.75% |
| 1 | 0.9322 | 0.2882 | 32.85% |
| 10 | 0.9988 | 0.0051 | 52.31% |
| 100 | 1.0000 | 0.000057 | 54.32% |

Штраф действительно уменьшает концентрацию и приближает доли к prior.
Это ожидаемое математическое свойство, **не измеренное улучшение точности**.
При lambda=1 смена prior меняет доли в среднем на 8.17% TV, при lambda=100 —
на 13.05%: сильная регуляризация усиливает зависимость от выбранного prior.

Все нормированные распределения с одним 030 имеют одинаковые маршрутные
итоги и WAPE по построению. Поэтому сила штрафа не выбиралась по маршрутной
ошибке; stop WAPE/MAE остаются null. Для подбора lambda и сравнения модели
долей с историческими долями нужна отдельная временная выборка реальных
московских остановочных наблюдений.

## Артефакт и проверка

[route12_scenario.csv.gz](runs/shares-20260927-v2/route12_scenario.csv.gz):
142 008 строк, 97 позиций × 61 день × 24 часа. `lambda=1`, равномерный prior —
иллюстративный выбор, не лучший по измеренной точности. `boardings` — дробное
ожидание, `prediction` — маршрутный 030, `share` — регуляризованная доля.
Ключ: route/direction_id/trip_id/stop_sequence/date/hour; stop_id сохранён.
`nonzero_probability` пуст: бинарная модель не обучалась. Статус обязателен:
`prior_only_entropy_scenario_not_fitted_blfs`, версия `F20260927-v2`.
Сохранены даты и статус поздней географии; все позиции доступны только по
сценарному предположению. Часы 1–4 — структурные нули, доли отсутствуют.
Рабочие вероятности и интервалы уверенности не выдумываются.

Баланс с 030 соблюдён с максимальной погрешностью 2.8e−12.
Полные профили всех lambda/prior сохранены в scenario_profiles.csv.gz.
Предыдущий запуск v1 сохранён; v2 использует устойчивую log-нормировку prior
в супервизируемой функции потерь. Сценарные численные результаты не изменились.

```sh

```

Выход должен быть новым. Для проверки сохранённого запуска указать
`ml/lab/stop_forecast/runs/shares-20260927-v2`. Проверяются хеши, уникальность,
баланс, ночные нули, нормировка, монотонность KL и честный статус результата.
Unit-тесты отдельно проверяют аналитический градиент, действие KL в обучении,
нулевые группы, отказ от неполных меток и пустой прогнозный набор. Синтетические
fixtures служат только проверке кода; ни их «качество», ни их коэффициенты
не записываются как исследовательский результат или московская модель.

Следующий шаг обучения: независимая разметка и подтверждённая историческая
поддержка → признаки окружения → обучение BL–FS и подбор lambda на первом
окне → фиксация модели → остановочная оценка на следующих 61-дневных окнах.
030, прежний аудит, backend/frontend и конкурсные посылки не изменены.
