# Регуляризация остановочной модели: исследование 27.09.2026

Уточнение пользователя: перенос модели из Коломны в Москву не обоснован.
Коломна остаётся примером обработки наблюдений, не основной обучающей
выборкой и не источником московских долей. Ниже — предложение для отдельного
исследования, не реализованный алгоритм и не новая версия рецепта 030.

## Найденные подходы

1. **Доли внутри маршрута.** Rahman, Yasmin, Eluru (2020),
   [joint binary logit + fractional split](https://doi.org/10.1016/j.tra.2020.06.015).
   Изучены аннотация и введение издателя, индексированный фрагмент авторского
   PDF; прямой GET авторской страницы PDF вернул 404.
   Модель описывает наличие спроса и долю остановки через характеристики
   окружения и транспорта. Обучение использует остановочные данные Орландо
   за май 2014 — декабрь 2016. Это аргумент за форму модели, а не доказательство
   возможности обучить её без остановочных наблюдений или перенести коэффициенты.
2. **Обучение по агрегированным ответам.** Derval, Docquier, Schaus (2019),
   [aggregate learning / PCD-LinExp](https://arxiv.org/abs/1907.00270).
   Прочитан текст PDF, особенно разделы 3.4–4: сначала вычисляются локальные
   положительные значения из внешних признаков, затем их сумма сравнивается
   с известным агрегатом. Исследование относится к населению, не трамваям.
   Применимость к TramCast — наша гипотеза. Авторы также показывают, что
   согласование с итогом способно ухудшить локальные ошибки.
3. **Энтропия и гравитационные модели.** Wilson (1967/1970),
   [первичное авторское объяснение](https://www.lis.ac.uk/stories/routes-to-interdisciplinarity-4-the-entropy-story),
   [книга](https://www.routledge.com/Entropy-in-Urban-and-Regional-Modelling-Routledge-Revivals/Wilson/p/book/9780415696319).
   Прочитаны авторское объяснение и карточка книги, не полный текст книги.
   Ограничения на потоки и транспортные издержки определяют распределение.
   Для нас полезен принцип минимального отклонения от явно заданного prior.
   Без информативных ограничений максимальная энтропия даёт равные доли.
4. **Косвенные наблюдения через время стоянки.** Sun, Schmöcker, Fukuda (2021),
   [Bayesian dwell-time model](https://doi.org/10.1016/j.trc.2021.103273).
   Прочитаны аннотация и доступные разделы издателя. Нужны фактические стоянки
   из AVL либо журналов дверей. Проверка выполнена на трёх автобусных маршрутах
   Сидзуоки; дополнительные подсчёты посадок улучшают оценку. Для наших текущих
   файлов этот вход отсутствует. Автобусную зависимость времени от посадок
   нельзя автоматически применять к многодверному московскому трамваю.

## Предлагаемая минимальная постановка

Это наша адаптация идей выше, не воспроизведение какой-либо статьи.
Индекс `i` обозначает направление, исторический вариант и вхождение остановки
в последовательность; `t` — календарный час. `Y_rt` — наблюдаемый маршрутный
счётчик успешных валидаций. Для начала общий небольшой набор коэффициентов:

```
mu_rit = e_rit * exp(beta' x_rit)
M_rt   = sum_i mu_rit
loss   = sum_(r,t in usable) w_rt * [M_rt - Y_rt * log(M_rt)]
         + lambda_beta * ||beta - beta_prior||²
```

`x` — исторически согласованные признаки Москвы: жилое/рабочее окружение,
доступность пересадки, час и тип дня, несколько взаимодействий с ними.
Признаки стандартизируются на обучающем периоде. Нулевой prior коэффициентов
предпочтительнее заимствованных неподтверждённых коэффициентов Коломны.
`e` — известная экспозиция, например плановые обслуживания в час, если такой
архив действительно получен. Это не фактически выполненные рейсы. Если
экспозиции нет, нельзя молча присвоить каждому часу одинаковый выпуск:
нужен явно ограниченный вариант модели без этого признака.

Poisson loss — предлагаемая функция для счётчиков, не заявление о доказанном
пуассоновском распределении. Пропуски исключаются; частичные счётчики нельзя
считать полными, а неизвестные коэффициенты регистрации — произвольно
восстанавливать. Ночные структурные нули обрабатываются отдельно от log(0).

После обучения ненормированной модели можно получить доли `p = mu / M`
и отдельный сценарий с маршрутным прогнозом 030: `Bhat = Rhat_030 * p`.
Это согласование прогнозных ожиданий, не способ разметить исторические события.
Исторический unassigned ledger остаётся неизменным. Для неполной географии
нужна явно нераспределённая часть; нормирование только по известным остановкам
не допускается. При `M=0` нормирование не определено, нужен статус unavailable.

## Что именно регуляризовать

- Небольшое число общих коэффициентов, L2-сжатие и ограниченный набор
  взаимодействий. Свободный эффект на каждую остановку/час пока не добавлять.
- При появлении обоснованного московского prior `q`: штраф
  `lambda_KL * sum p_i log(p_i/q_i)`, с положительным `q` на допустимой поддержке.
  Число POI само по себе не устанавливает вероятность посадки. Гравитационный
  prior потребует масс происхождения/притяжения, стоимости пути и калибровки.
- Временная гладкость только внутри сопоставимых режимов работы. Не сглаживать
  через закрытия, смены схем и рабочие/нерабочие окна как через обычные часы.
- Графовую гладкость оставить вторым шагом. Если потребуется, штрафовать
  остаточные эффекты сходных остановок, а не сами посадки географических соседей:
  пересадочный узел может обоснованно иметь резкий пик.

## Идентифицируемость и обязательные проверки

Если сразу задать `B_i = Y * softmax(z)_i`, сумма всегда равна `Y`.
Ошибкой маршрутной суммы невозможно обучить `z`: эта ошибка не зависит от долей.
Поэтому обучение по суммам выполняется **до** нормирования и с общими
параметрами между маршрутами. Даже тогда успех не гарантирован: маршрутных
пространственных конфигураций мало, признаки могут быть взаимозаменяемыми.

Перед реализацией проверить историческую сеть, доступность признаков и
полноту счётчиков. Затем заморозить набор признаков/параметров и исследовать:

1. Ранг и обусловленность якобиана агрегатных ожиданий по параметрам;
   это локальная диагностика, не доказательство глобальной идентифицируемости.
2. Изменение остановочных долей при разных prior и силе сжатия среди моделей
   с близкой маршрутной ошибкой. Широкий разброс означает, что данные не
   определяют распределение. Диапазон чувствительности не называть
   калиброванным доверительным интервалом.
3. Временные окна из исходного протокола и дополнительное исключение целых
   маршрутов. Оценка сумм показывает только перенос агрегатного прогноза.
4. После получения московского остановочного эталона — WAPE/MAE долей и
   посадок, отдельно от route score. До этого статус только сценарный.

Регуляризация выбирает устойчивое решение среди допустимых, но не добавляет
независимых наблюдений. На одном итоге 100 варианты (90, 10) и (10, 90)
неразличимы по маршрутному качеству. Выбор одного из них должен иметь явное
основание в признаках/prior и проходить проверку локальными фактами.

Существующий протокол проверяемого прогноза не изменён. Реализации и метрик
этой новой гипотезы пока нет. Основное направление дальнейшего исследования —
московская модель с регуляризацией, не перенос коломенских коэффициентов.
