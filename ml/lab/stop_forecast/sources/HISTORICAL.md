# Исторические источники: проверка 27.09.2026

По дополнительной просьбе пользователя поиск расширен на прежние годы и
другие трамвайные системы. Получены три набора, а не только ссылки на статьи.
Они пригодны для разных частей исследования. Ни один не является эталоном
успешных валидаций на московских трамвайных остановках.

Файлы сохранены локально в `dataset/external/stop_history_20260927/`, вне Git.
URL, размер, время получения и SHA256 — в
[historical_manifest_20260927.json](historical_manifest_20260927.json).
Рецепт 030, результаты аудита v1/v2 и московские прогнозы не изменены.

## 1. Коломна: реальные ручные подсчёты на остановках

Источник: [репозиторий авторов](https://github.com/kolomna-trams/open-data),
[закреплённый CSV](https://github.com/kolomna-trams/open-data/blob/ffae7d164badf9b609b9e45ff6f8ee1ae7d2fcb5/crowd/crowd_raw.csv).
Получен обычным HTTPS GET. Версия репозитория:
`ffae7d164badf9b609b9e45ff6f8ee1ae7d2fcb5`.

[Описание сбора авторами](https://kolomna-trams.ru/workshop/articles/)
указывает ручную регистрацию входящих и выходящих пассажиров с временем
и остановкой. [Статья Балабанова и Судакова](https://keldysh.ru/papers/2026/prep2026_12.pdf),
таблица 2, определяет `tram_no` как номер маршрута, `inbound` как входящих,
`outbound` как выходящих, `passengers` как число в вагоне после остановки.
Это подсчёт людей, а не успешных оплат. Описание статьи относится к
сентябрю 2024 — июню 2025; текущий CSV уже дополнен 2026 годом.

Измерено по всему скачанному CSV:

| Проверка | Результат |
|---|---|
| Записи / поездки `travel_id` / уникальные `stop` | 730 / 75 / 85 |
| Маршруты | 1, 2, 3, 4, 5, 7, 9, 10 — номера Коломны |
| Даты | 26.09, 04.10, 06.10, 11.10.2024; 02.05, 12.06.2025; 16.02, 16.04.2026 |
| Часы с записями | 08–19 |
| До конкурсного начала 01.11.2025 | 600 строк, 50 поездок, 6 дней, 1 729 входящих |
| Весь файл: входящие / выходящие | 2 195 / 1 949 |
| Полные дубли / отрицательные счётчики | 0 / 0 |
| Пропуски | `train`: 699; `odometer`: 2; `interval_same`: 5 |
| Непоследовательные даты/маршруты внутри `travel_id` | 0 |
| Убывание времени внутри поездки в порядке файла | 0 |
| Поездки с повторным `stop` | 1 |

Девять переходов внутри поездок нарушают равенство
`passengers[t] = passengers[t-1] + inbound[t] - outbound[t]`:
`travel_id` 17 (позиция 22), 19 (3), 21 (1), 33 (6), 35 (1, 2, 3),
64 (4, 6), позиции от нуля в порядке файла.
Это несогласованность полей, причина не установлена. Для первых строк
равенство с начальным количеством 0 не требуем: исследователь мог сесть
в уже заполненный вагон. Независимая перепроверка ручных подсчётов отсутствует.

**Применение:** реальный небольшой пример для проверки схемы, повторных
остановок, частичных счётчиков и сравнения простых моделей на отдельных
наблюдаемых посещениях. Направление и вариант не заданы отдельными полями:
нужен справочник автора, нельзя назначать их по номеру маршрута.
Почасовая сумма обследованных вагонов остаётся частичным счётчиком.
Восемь дней не дают непрерывного 61-дневного теста; пустые даты не нули.
Московские номера маршрутов с коломенскими не связывать.
В просмотренном дереве репозитория нет LICENSE: условия повторного
распространения не подтверждены; файл не добавлен в Git и не опубликован.

## 2. Москва: пассажиропоток метро за 2021–2025 годы

Первоисточник: [data.mos.ru, набор 62743](https://data.mos.ru/opendata/62743).
Прямое открытие снова не удалось. Найдено публичное зеркало автора
[исследования HSE Design](https://hsedesign.com/project/analiz-4e76e86f90634eeeb0d42c5de35e42d0),
ссылающегося на версию 1, выпуск 32 портала и дату обращения 26.01.2026.
Скачан [Metro.zip](https://disk.360.yandex.ru/d/UUrUv2RA7TiPiA)
через публичный download endpoint Яндекс Диска. Прочитан только
`Metro/data/PassengerTraffic.csv`; чужой notebook не выполнялся.
Совпадение зеркала с оригинальной выгрузкой по хешу проверить не удалось.

Фактические поля: `NameOfStation`, `Line`, `Year`, `Quarter`,
`IncomingPassengers`, `OutgoingPassengers`, `global_id`.
После удаления второй строки с русскими названиями столбцов: **5 838 строк**,
20 кварталов от I кв. 2021 до IV кв. 2025, 263 названия станций,
315 пар станция–линия. Дублей ключа станция–линия–год–квартал нет.
В 173 строках хотя бы один из двух счётчиков равен нулю; считать их
доказательством отсутствия спроса нельзя без проверки объединённых входов
и других правил учёта.

**Применение:** кандидат на признак притяжения ближайшего пересадочного узла
и его многолетнего изменения. Нужны историческая география переходов,
проверка нулей и отдельное измерение добавочной пользы. Это квартальная
статистика метро, не почасовые посадки в трамвай и не готовые остановочные
доли. IV квартал 2025 пересекает конкурсный горизонт: держать отдельно,
не подмешивать в основной исторический эксперимент. Для строгой имитации
прогноза из прошлого также нужны даты публикации квартальных сведений.

## 3. Цюрих: архив остановочных профилей с 2014 года

[Официальный каталог VBZ](https://data.stadt-zuerich.ch/dataset/vbz_fahrgastzahlen_ogd)
предлагает годовые архивы 2014–2025 под CC0.
Скачан и полностью прочитан
[архив 2018](https://data.stadt-zuerich.ch/dataset/vbz_fahrgastzahlen_ogd/download/Fahrgastzahlen_2018.zip):
`Reisende_VBZ.csv`, `LINIE.csv`, `HALTESTELLEN.csv`, `TAGTYP.csv`.

Всего **910 781 строка**. После связи `Linien_Id` с `LINIE.csv` и фильтра
`VSYS == T`: **367 892 строки, 15 трамвайных линий, 198 остановочных ID**.
528 трамвайных строк имеют `Anzahl_Messungen == 0`.
Ключ тип дня–плановый рейс–направление–последовательность уникален в
трамвайном подмножестве. Есть отдельные `Einsteiger`, `Aussteiger`,
`Besetzung`, время отправления и число измерений.

Поставщик прямо определяет значения как усреднённые по типам дней профили,
полученные по части оборудованных счётчиками вагонов. Неизмеренные рейсы
интерполируются. Поэтому это **оценки типичного профиля**, не исходный журнал
конкретных календарных дат. `Anzahl_Messungen > 0` тоже не превращает среднее
в ежедневный факт.

**Применение:** техническая проверка методов остановочных долей и ключей
на более крупной сети, возможное исследование переноса признаков.
Нельзя размножить профиль по датам и объявить это независимым 61-дневным
тестом. Качество на этих профилях не доказывает качество на Москве.

## Практический следующий шаг

Уточнение после обсуждения с пользователем: основной кандидат теперь —
[модель по московским агрегатам с регуляризацией](REGULARIZATION.md).
Коломна ниже остаётся только дополнительным примером обработки данных,
а не источником коэффициентов для Москвы.

1. Для отдельного пилота обработки наблюдений выбрать Коломну: сохранить
   исходные строки, пометить ошибки баланса, отделить 2026 год, получить
   соответствия направлений и остановок. Разбивать по целым датам/поездкам,
   не случайным строкам. Возможная задача — посадки при наблюдаемом
   посещении остановки; полный час по всему маршруту здесь не наблюдается.
2. Для будущей московской модели проверить квартальный поток метро как
   внешний признак после появления московской остановочной цели. До этого
   нельзя измерить, улучшает ли он распределение.
3. Цюрих оставить дополнительным набором для исследования профилей.
   Прямое обучение московских остановочных долей на чужих stop_id не имеет
   обоснования. Проверяемый перенос потребует московских наблюдений.

Поиск дал доступные данные для разработки и ограниченного исследования,
но московский критерий успеха остаётся невыполненным. Искусственные метки
и новые прогнозные метрики не создавались.
