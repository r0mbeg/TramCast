# Пакет для интеграции: расчётные посадки №12

**Готов локальный пакет**, без подключения к Go/UI и без публикации:
[releases/route12-entropy-v1](releases/route12-entropy-v1/).
Версия `E20260927-v1-88f891a83f8f266f`, схема `tramcast.stop-estimate.v1`.
Пакет содержит 142 008 почасовых оценок для 97 позиций (95 ID остановок),
двух направлений №12, 1 ноября–31 декабря 2025. Все 1 464 почасовых итога
точно сохраняют 030: всего 1 964 916 успешных валидаций в прогнозе.

Пользовательское название: **«Расчётное распределение посадок»**.
Пояснение: «Оценка по маршрутному прогнозу и предположениям модели;
точность по отдельным остановкам не проверена».
Не показывать эти числа как измерения, заполненность вагона, физические
входы всех пассажиров или прогноз с маршрутной точностью на каждой остановке.

## Что передать разработчику

Передача идёт через GitHub: весь каталог `releases/route12-entropy-v1/`
и эта инструкция входят в Git. Отдельный ZIP не нужен. После получения
ветки выполнить проверку пакета из раздела ниже перед импортом.
Формат таблиц — UTF-8 CSV,
разделитель `;`; `stop_estimates.csv.gz` сжат gzip. Метаданные — JSON.
Имена файлов и SHA256 перечислены в `manifest.json`: проверить их перед импортом.
Исходные сырые оплаты, исходная служебная книга и веса 030 для чтения пакета
не требуются. Пути в `manifest.inputs` документируют происхождение сборки,
а не являются требованием загрузить эти файлы в Go или публиковать их.

| Файл | Назначение |
| --- | --- |
| metadata.json | Версии, период, статус, подписи, метод и ограничения |
| occurrences.csv | 97 позиций схемы, ключи источника, названия и координаты |
| profiles.csv | 3 880 долей: 97 позиций × 20 рабочих часов × 2 типа дня |
| route_forecast.csv | 1 464 исходных целых почасовых прогноза №12 из bundle 030 |
| stop_estimates.csv.gz | 142 008 готовых дробных ожиданий и целых оценок |
| route_balance.csv | Итог маршрута, сумма распределённого и остаток для каждого часа |
| sensitivity.json | Зависимость долей от альтернативных допущений, не точность |
| manifest.json | Идентификатор пакета, SHA256 входов и семи файлов результата |

## Ключи и привязка к приложению

`occurrence_id` — непрозрачный ключ позиции, например
`catalog:12:2043157:1`. Его составляющие уже вынесены в отдельные поля:

| Поле occurrences | Тип / смысл |
| --- | --- |
| route | int, номер маршрута, здесь 12; не внутренний route_id БД |
| source_route_id | string, ID маршрута в книге, здесь 4428 |
| direction_id | int, 0 или 1 |
| pattern_key | string, исходный trip_id, 2043157 или 2043158 |
| stop_sequence | int, порядковый номер позиции; 1–50 или 1–47 |
| source_stop_id | string, ID остановки источника; **не внутренний stop_id БД** |
| stop_name, stop_lat, stop_lon | Название и координаты из каталога приложения |
| start_date, actual_date, stop_mode | Исходные поля книги без переинтерпретации |
| boarding_eligibility | assumed_unverified: допустимость посадок принята условно |
| historical_validity_verified | false |

В приложении найти внутренний маршрут по route_number=12. Затем сопоставить
позиции по `(внутренний route_id, pattern_key, stop_sequence)` с проверкой
direction_id. На сервере дополнительно сверить `source_stop_id` с каталогом.
В существующем API `/api/routes/{route_id}/stops` есть pattern_key,
stop_sequence, direction_id и внутренний stop_id; исходный ID не следует
подставлять вместо этого stop_id. Совпадение названий не используется как ключ.

Повторный source_stop_id в другом направлении остаётся другой позицией.
Для карты одной физической остановки можно сложить уже целые оценки всех
отображаемых позиций с этим исходным ID. После выбора одного направления
его сумма является только частью маршрутной, а не копией полного итога.

При расхождении каталога **не перенормировать** доли оставшихся остановок.
Несопоставленные готовые целые оценки складываются в маршрутный `unassigned`.
Если не сопоставлено ничего, весь итог остаётся нераспределённым.
Отсутствующий результат не показывать нулём. Этот пакет не содержит других
маршрутов; для них наличие маршрутного прогноза не означает готовность остановок.

## Таблица оценок

Ключ хранения: `(package_version, route, date, hour, occurrence_id)`.
Версия берётся из metadata и должна сопровождать импорт всего пакета.
Одинаковые date/hour из разных версий не смешиваются.

| Поле stop_estimates | Смысл |
| --- | --- |
| route, date, hour, occurrence_id | Ключ; дата календарная, час 0–23, Europe/Moscow |
| share | Доля всего маршрутного часа, не отдельного направления |
| expected_validations | Дробное математическое ожидание; не наблюдение |
| estimated_validations | Неотрицательное целое int64 для интерфейса/суммирования |
| estimate_status | scenario_estimate либо structural_zero для часов 1–4 |

Час 5 соответствует только 05:30–05:59:59 — очищенный итог уже учитывает это.
В часах 1–4 share=0 и все оценки нулевые по правилу очистки; это не доказательство
того, какие остановки обслуживались. Нулевая целая оценка рабочего часа может
возникнуть при округлении и не означает доказанное отсутствие спроса.
Сутки/недели/месяцы складываются из `estimated_validations`; повторно округлять
`expected_validations` по отдельности нельзя.

`route_balance.csv`: `route_prediction = allocated_prediction + unassigned_prediction`.
В этом полном сценарном снимке остаток равен 0. Это означает только полное
распределение по допущению, а не 100% подтверждённую привязку событий.
`catalog_mapping_fraction=1`, `verified_stop_observation_coverage=0`,
`real_service_coverage=null`, `stop_wape=null`, `stop_mae=null` — разные показатели.

## Математика и зафиксированные допущения

Исходные s — положительные доли агрегатной модели B-v4, сохранённые в F-v2.
Та модель обучалась на московских маршрутных суммах, не остановочных целях.
q_i=1/97; lambda=1. Решение:

`min KL(p||s) + KL(p||q)`, то есть `p_i = sqrt(s_i*q_i) / sum_j sqrt(s_j*q_j)`.

Это однозначный оптимум данной выпуклой задачи. Он не доказывает, что
пассажиры действительно распределяются так. Lambda=1 сохранена из ранее
проверенного сценария; маршрутный score не использовался для её выбора.
Сырые s, prior q и итог p сохранены для всех 40 контекстов. Будни — пн–пт,
выходные — сб/вс; государственные переносы и праздники отдельно не учтены.

Оба направления нормируются вместе. Предполагается, что весь поздний снимок
доступен на всём горизонте: книга задаёт start_date=20.12.2025 и
actual_date=05.02.2026, поэтому это не исторически подтверждённая схема
ноября–декабря. Смысл stop_mode не установлен; коды не использованы для
объявления технических/посадочных/высадочных позиций. Это существенное
ограничение сценария, сохранённое в metadata и в каждой позиции.

Итоговые доли направления 0: 51,00–51,67%; направления 1: 48,33–49,00%.
Максимальная доля одной позиции достигает 9,66% (будний час 0, первая позиция
«Восточное Измайлово», stop_mode=5). Это следствие исходной модели и допущений,
а не измеренный поток этой остановки; его нельзя представлять как установленную
закономерность. При lambda=10 средняя доля перераспределяемой массы относительно
выпуска — 17,51%, при альтернативном prior с притяжением центра — 9,52%.
Сравнение с равномерным контролем даёт 19,38%. Подробности в sensitivity.json.
Это чувствительность, не проценты ошибки и не доверительные интервалы.

## Целочисленное согласование

030 уже даёт целое T. Для всех позиций часа вычисляются T*p_i, берутся целые
части и оставшиеся единицы отдаются максимальным дробным остаткам.
Равные остатки разрешаются порядком `(route, direction_id, pattern_key,
stop_sequence, source_stop_id)`: числа сравниваются как числа, ключи — как строки.
В реализации веса преобразуются в точные рациональные числа из десятичных
записей и нормируются; так сохраняется сумма даже у границы int64.
При воспроизведении из profiles.csv сохранять десятичную точность весов:
читать строки как рациональные числа либо использовать round-trip разбор
float; стандартное сокращение точности CSV-парсером не является частью метода.

Готовый экспорт уже округлён. Если интегратор применит profiles к новым
маршрутным итогам, потребуется **новая версия результата**, тот же алгоритм
округления и явное сохранение сценарных ограничений/периода применимости.
Подмена route_forecast.csv внутри существующего пакета запрещена проверкой SHA256.
Этот документ не меняет существующий Protobuf-контракт и не реализует новое API.

## Проверка и воспроизведение

```sh
.venv/bin/python ml/lab/stop_forecast/test_app_package.py \
  ml/lab/stop_forecast/releases/route12-entropy-v1
.venv/bin/python ml/lab/stop_forecast/build_app_package.py \
  --out /tmp/tramcast-route12-another-build
```

Новый каталог должен отсутствовать. Builder требует локальные сохранённые
B/F-артефакты, исходные справочники для сверки и bundle 030, но не читает raw
оплаты и не запускает GPU/обучение. Тест экспортированных таблиц проверяет
их хеши без необходимости чтения входов из manifest.inputs.

Пройдены: int64/отрицательные/NaN, нули, равные остатки, повторные stop_id,
инвариантность к перестановке строк, отказ при неполных профилях и изменённой
географии, все ключи/суммы/ночи, независимая проверка формулы sqrt(s*q),
остаток при частичном сопоставлении. Повторная сборка дала **побайтовое
совпадение всех восьми файлов**, включая manifest. Отдельный результат
проверок хранится в `sources/app_package_verification_20260927.json`.
