## Prior и расчёт

Для каждой позиции рассчитано расстояние до ближайшего из 1 020 входов
метро в архиве 23.10.2021. Несколько входов станции не суммируются.
Счётчики пассажиров метро не используются; связь расстояния с посадками
остаётся предположением. Нет гарантии полноты входов в 2025 году и
подтверждённых пеших путей. Отсутствие близкого архивного входа не доказывает
отсутствие метро или спроса.

На допустимой посадочной поддержке:

`a_i = exp(-distance_i / 500)`

`q_i = 0.5/n + 0.5*a_i/sum(a)`

`p_i = sqrt(s_i*q_i) / sum_j sqrt(s_j*q_j)`

Это решение `min KL(p||s) + KL(p||q)`. Оба направления нормируются вместе;
маршрутная сумма не выдаётся каждому направлению отдельно. Параметры
зафиксированы в [протоколе](NETWORK_PROTOCOL.md) до расчёта и не подобраны
по остановочной точности. Равномерная составляющая даёт положительный
минимальный вес всем разрешённым позициям.

Для 1/7/11/12 используются 40 исходных профилей B/F: 20 рабочих часов ×
будни/сб–вс. Для пяти новых маршрутов исходные доли равномерны, поэтому
конечные доли пропорциональны sqrt(q), одинаковы по часам/типам дня.
Их абсолютные числа меняются с маршрутным прогнозом. Коэффициенты №12
не перенесены на эти маршруты; новые доли не обучены на остановочных целях.
Для 5 все значения нулевые независимо от формально сохранённого профиля.

## Файлы и интеграция

Передача — через GitHub, без ZIP. Для импорта нужны только файлы выпуска;
сырые оплаты, исходная служебная книга и веса 030 не нужны.

| Файл | Назначение |
|---|---|
| metadata.json | Версии, правила, происхождение, лицензии и ограничения |
| manifest.json | SHA256 входов сборки и всех файлов выпуска |
| occurrences.csv | 604 позиции, названия, координаты, направления и признаки prior |
| profiles.csv.gz | 24 160 строк: исходная доля, prior, итоговая доля и их происхождение |
| route_forecast.csv | 14 640 исходных маршрутных целых значений 030 |
| stop_estimates.csv.gz | 884 256 почасовых дробных ожиданий и целых оценок |
| route_balance.csv | Маршрутный итог, распределённое и несопоставленное |
| coverage.csv | Число позиций, метро-кандидатов и источник долей по маршрутам |
| sensitivity.csv | Средняя/максимальная TV относительно фиксированных альтернатив |

CSV: UTF-8, разделитель `;`, даты `YYYY-MM-DD`, час 0–23, Europe/Moscow.
Сначала проверить `manifest.outputs`. Версии и хеши меняются при изменении
входов или модели; нельзя подменять файл под прежней версией.

Идентификаторы — **ключи источников, не внутренние ID PostgreSQL**:

- `source_route_id`: ID книги или `osm:relation/<route_master>`;
- `pattern_key`: ID шаблона книги или `osm:relation/<route>`;
- `source_stop_id`: ID книги или `osm:node/<node>`;
- `direction_id`, `stop_sequence`: направление и порядковое вхождение;
- `occurrence_id`: локальный уникальный ключ пакета; связывает profiles/estimates
  с occurrences. Его формат не нужно разбирать, использовать как строку.

Сопоставлять позиции по `(source_route_id, pattern_key, direction_id,
stop_sequence, source_stop_id)`. Для OSM направление задано той же явной
таблицей, что в импорте Go, а не сортировкой ID relation. Повторные вхождения
одной физической остановки сохраняются; их объединение допустимо лишь
в отдельном представлении после суммирования готовых целых значений.

В estimates сохранены прежние поля: `route`, `date`, `hour`, `occurrence_id`,
`share`, `expected_validations`, `estimated_validations`, `estimate_status`.
`expected_validations` — дробное ожидание T*p, `estimated_validations` —
неотрицательное целое после largest remainder. Не округлять повторно;
суточные/месячные суммы складывать из готовых целых часов.

Статусы:

- `scenario_estimate`: расчётная оценка, в том числе округлённый ноль;
- `structural_zero_nonworking`: часы 1–4, share=0;
- `scenario_zero_exit_only`: рабочий час позиции OSM «только высадка»;
- `route5_no_history_zero_fallback`: согласованный fallback, не измеренный ноль.

Для маршрута 5 статус fallback имеет приоритет, включая ночные часы.
Сохранённый профиль 5 не означает существование изученного пассажиропотока.
У других маршрутов нулевой маршрутный прогноз рабочего часа не превращается
в доказательство отсутствия спроса. Остановочные наблюдения отсутствуют:
`stop_wape=null`, `stop_mae=null`, `verified_stop_observation_coverage=0`,
`real_service_coverage=null`, `occupancy_available=false`.

`route_prediction = allocated_prediction + unassigned_prediction`.
В пакете весь маршрут распределён условно по снимку, поэтому остаток нулевой.
Если часть позиций не сопоставилась в приложении, их целые значения сохранить
как unassigned; **не перенормировать оставшиеся доли**. Наличие всей географии
не равно полному покрытию реального движения или независимых наблюдений.

## Воспроизведение

Из корня репозитория, Python с зависимостями `ml/lab/requirements.txt`:

```sh
.venv/bin/python ml/lab/stop_forecast/test_network_package.py \
  ml/lab/stop_forecast/releases/network-entropy-v1
.venv/bin/python ml/lab/stop_forecast/network_package.py build \
  --inputs ml/lab/stop_forecast/inputs/network-v1 \
  --out /tmp/tramcast-network-rebuild
```

Каталог выхода должен отсутствовать. `inputs/network-v1` содержит компактные
зафиксированные позиции с расстояниями, исходные B/F-доли и manifest.
Для обычной сборки дополнительные скачивания и локальный dataset не нужны.
Для полного восстановления этих входов по архивам:

```sh
.venv/bin/python ml/lab/stop_forecast/network_package.py prepare \
  --out /tmp/tramcast-network-inputs-new
```

Последняя команда требует локальные G-v1 `entrances.csv` и F-v2
`scenario_profiles.csv.gz`, проверяет их хеши и использует очищенную книгу
и OSM из `data/`. Исходные архивы, способы получения и ограничения перечислены
в [G-v1](METRO_ACCESS.md), [F-v2](SHARES_REPORT.md) и manifest входов.
OSM: © участники OpenStreetMap, ODbL 1.0. Для метро сохранены исходные
условия архива и расхождение с лицензией страницы зеркала; лицензия кода
не подменяет условия внешних данных. Архив входов метро не добавляется в Git.

## Что сравнивается

Средняя TV относительно uniform prior: примерно 4,6–11,2% массы по маршрутам;
для №12 — 6,96%. Это изменение распределения, не измеренная ошибка или выигрыш.
В sensitivity также сохранены alpha=0.25/0.75, расстояния 300/800 м,
lambda=0/10 и равные доли. Большой вес конечной остановки в исходной B/F
не становится подтверждённым потоком благодаря новому prior.

Новый пакет не меняет маршрутную модель, её прогнозы или её метрики.
Остановочную точность нельзя оценить по совпадению маршрутных сумм.
Интеграция Go/UI, развёртывание и конкурсная отправка не выполняются.
