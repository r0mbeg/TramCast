# Контракт остановочных артефактов S1 — проект до получения наблюдений

Для отдельно согласованных сценарных оценок приложения действует
[схема E-v1](APP_PACKAGE.md). Указанный ниже запрет выпуска без stop truth
относится к проверенному остановочному прогнозу S1, а не к явно маркированному
сценарному пакету. Исторические требования к наблюдениям сохранены.

Это схема для последующего ML-пилота и интеграции другим разработчиком.
Рабочий gRPC, 030 и маршрутные пакеты не меняются. Остановочный прогноз пока
не выпущен. `availability.json` описывает отсутствие результата, не прогноз.
Единица — успешные валидации, условно называемые посадками; не уникальные
люди, не все физические входы и не заполненность салона.

## Источник для подготовки

Предпочтителен исходный журнал подтверждённых посадок со stop occurrence
и независимым эталоном. Альтернатива — AFC + исторические фактические stop
visits или AVL + интервальная связь устройства и вагона. Минимальные поля:

- AFC: устойчивый ключ события (или source file + номер строки), device_id,
  vehicle_id/garage_number, event_time с зоной, validation_result, route number.
- Связь: device_id, vehicle_id, valid_from/valid_to, provenance; отсутствие
  пересекающихся противоречивых связей. Номер выхода не уникален сам по себе.
- Stop visit: vehicle_id, service_date, trip_instance_id, route, direction_id,
  pattern_key, stop_sequence, source_stop_id, arrival/departure timestamps,
  actual/planned indicator и качество часов. При GPS вместо stop visits:
  координаты, время, точность, частота, разрывы и версия map matching.
- Схема движения: source namespace, route number↔source route ID, direction,
  variant, stop occurrence, даты действия и отдельно received/published_at.
  Не объединять разные ID по совпадению названий. GTFS trip template из книги
  не равен фактическому trip_instance_id.
- Полнота: ожидаемые и фактические рейсы/устройства, heartbeat/доставка пакетов,
  отмены/сбои; независимые ручные stop visits или проверенные оператором связи.

Период — январь–октябрь 2025 и действующая/планируемая схема ноября–декабря.
Начать можно с маршрута-кандидата, но несколько рейсов позволят проверить
привязку, а не доказать качество 61-дневного прогноза.

## Наблюдения (UTF-8 CSV, `;`)

Ключ: `(route, network_version, direction_id, pattern_key, stop_sequence,
source_stop_id, date, hour)`. Источник входит в ID (`workbook:…`, `osm:…` или
пространство имён поставщика). Сочетание pattern+sequence различает повторные
посещения одной остановки. В одном направлении могут быть несколько вариантов.

| Поле | Тип и смысл |
|---|---|
| route | Положительный номер маршрута, не внутренний ID Go |
| network_version | Неизменяемая версия датированной схемы |
| direction_id, pattern_key | Направление и вариант; неизвестные не угадывать |
| stop_sequence, source_stop_id | Позиция посещения и ID остановки |
| date, hour | Календарная дата Москвы и час 0–23 |
| observed_boardings | Целый неотрицательный счётчик или null |
| estimated_boardings | Отдельная восстановленная оценка или null |
| observation_status | Статус ниже |
| matched_events, ambiguous_events | Счётчики подтверждённых и неоднозначных связей; ambiguous не прибавлять к stop truth |
| expected_visits, observed_visits | Числа рейсов/посещений либо null, если неизвестны |
| coverage_fraction | Только измеренное покрытие либо null; не считать автоматически 1 |
| source_version, linkage_version | Хеши источников, правил связи и параметров |
| evidence_ref | Ссылка на локальный журнал происхождения без личных данных |

Статусы различаются явно:

- `structural_zero`: 0 по согласованному рабочему окну; требуется известная
  действующая остановочная сетка. Это не замер валидатора.
- `observed_complete`: счётчик, включая 0, с внешним подтверждением полноты.
- `observed_partial`: известная неполная регистрация, счётчик — нижняя граница.
- `observed_unknown_completeness`: регистрация есть, полнота не установлена.
- `missing`: observed_boardings=null. Отсутствие событий не заполнять фактом 0.
- `restored_estimate`: estimated_boardings заполнено; фактический исходный
  счётчик/статус сохраняются отдельно, оценка не попадает в эталон теста.

Ночной структурный ноль маршрутной цели не подтверждает, какие остановки
действовали в этот день. Поэтому без исторической схемы даже ночные строки
остановок не синтезируются. Маршрут 5 — отдельный маршрутный fallback;
отсутствие истории не является доказательством остановочной точности.

Валидация не всегда происходит непосредственно в момент посадки: задержку
оплаты и рассогласование часов нужно измерить на независимых рейсах. Событие
между остановками нельзя без проверки назначать ближайшей остановке.

## Баланс

Для каждого route×date×hour после исходной очистки:

`route_observed_counter = sum(unique_matched_events) + ambiguous + unmatched`.

Никакое событие не может попасть в две позиции/направления. Unassigned bucket
учитывается на уровне маршрута и не является фиктивной остановкой. Неполный
список размеченных остановок не нормируется до 100% маршрутных посадок.
Нужно отдельно показывать покрытие разметкой и покрытие регистрации.
При сравнении с APC учитывать, что физические входы и успешные оплаты —
разные цели; APC без согласования определения не является точным AFC truth.

## Версионированный прогноз (после прохождения проверки)

Manifest: `schema_version`, `forecast_version`, `model_version`,
`dataset_version`, `network_version`, `linkage_version`, `created_at`,
`history_end`, `forecast_from`, `forecast_to`, `timezone=Europe/Moscow`,
`value_kind=stop_boardings_forecast`, список файлов с SHA256, параметры,
разбиения/маска оценки, coverage и ссылки на независимый эталон.
`occupancy_available=false`; точность остановок не наследуется от рецепта 030.

CSV имеет ключ наблюдений и `prediction` (int64≥0), `value_kind`,
`forecast_version`. Интервал `[2025-11-01,2026-01-01)`, все 1464 часа на каждую
**действующую** позицию, с явной политикой изменений сети внутри горизонта.
Новые/закрытые варианты требуют отдельного указания доступности или сценария.
Нельзя выдавать сетку позднего снимка за исторически действующую.

Для прямой модели округление half-up один раз. Для долей с согласованием
сначала округлить маршрутный итог, затем largest remainder по всем
направлениям/вариантам/позициям и unassigned bucket вместе; tie-break —
лексикографический порядок полного ключа, закреплённый в manifest.
Сумма равна выбранному маршрутному итогу, а не отдельной его копии на направление.
Оценивать после того же округления, которое отдаётся потребителю.
Дневные/месячные суммы складываются из сохранённых часов.

При отсутствии stop truth manifest готового прогноза и forecast.csv
не создаются. Возвращается availability со `status=blocked`, причинами,
`forecast_artifact=null`, `metrics=null`; это не пустой успешный ответ.

## Перенос на другие маршруты

1. Получить пилотные данные, проверить ключи, даты и часы; отложить рейсы для
   независимой проверки связи, не выбирая допуски по ним.
2. Подтвердить полноту/маски и баланс, затем провести замороженные 61-дневные
   сравнения из PROTOCOL.md. Если данных мало — честно уменьшить утверждение
   о готовности, а не объявлять короткую проверку доказательством дальнего качества.
3. Для 1,7,11 получить исторические варианты (поздний XLSX не заменяет их).
   Для 17,25,26,28,50 дополнительно получить историческую сеть: OSM-снимок 2026
   даёт географию, но не полноту схем 2025 и не пассажирские наблюдения.
4. Для каждого маршрута заново измерить coverage, конфликты device/vehicle,
   качество привязки, баланс и ошибку. Перенос весов допускается только как
   явно проверяемая гипотеза; неподтверждённые маршруты оставить unavailable.
5. Маршрут 5 не имеет успешной истории: отдельный холодный старт/сценарий,
   пока нет реальных наблюдений. Нулевой конкурсный fallback 030 сохранить.

Для заполненности после остановки отдельно нужны высадки, начальное число
пассажиров и состав/вместимость конкретного рейса; текущие данные их не дают.
