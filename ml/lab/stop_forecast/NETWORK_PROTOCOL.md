# E-network-v1: протокол до расчёта

Поручение: расширить согласованный сценарий на 1, 5, 7, 11, 12, 17, 25,
26, 28, 50. Выпуск №12 E-v1 остаётся неизменным контролем. Новые результаты
не являются наблюдениями или доказательством остановочной точности.

## Фиксированные входы и поддержка

- Маршрутные целые прогнозы: `ml/bundles/030`, 01.11–31.12.2025, все 24 часа.
  Новый расчёт 030 и обучение моделей не запускаются.
- География: очищенная книга `data/catalog/catalog.xlsx` и снимок
  `data/osm/tram_routes.json`. Направления OSM совпадают с явной таблицей
  `catalog_service.OSMRoutes`; ID источников соответствуют импорту приложения.
  Схемы поздние, доступность каждой позиции на всём горизонте — допущение.
- `stop_exit_only` OSM получает нулевой посадочный вес, но остаётся в выходе.
  Неизвестные коды `stop_mode` книги не интерпретируются. Повторные вхождения
  сохраняются отдельно; оба направления нормируются вместе, без удвоения суммы.
- Для 1, 7, 11, 12 исходные s — зафиксированные доли B/F (uniform, lambda=0).
  Для 17, 25, 26, 28, 50 исходные s равномерны среди допустимых позиций:
  коэффициенты другого маршрута не переносятся. Для 5 все значения нулевые.

## Prior на основе данных

Из G-v1 берём 1 020 координат входов метро, снимок 23.10.2021, и вычисляем
расстояние d до ближайшего входа для каждой позиции. Это географические
наблюдения, не трамвайные посадки; актуальность и пешая доступность не доказаны.
Используется ближайший вход, поэтому дополнительные входы станции не суммируют
её вес. Квартальные потоки метро и направление выхода из метро не используются:
достоверного сопоставления всех остановок со станцией/линией и часовыми потоками нет.

На допустимой посадочной поддержке из n позиций:

`a_i = exp(-d_i / 500 м)`

`q_i = (1-alpha)/n + alpha * a_i/sum(a)`; основной alpha=0.5.

`p = argmin KL(p||s) + lambda*KL(p||q)`, основной lambda=1.

Радиус, alpha и lambda — фиксированные сценарные параметры, не оценки,
подобранные по остановочной точности. Uniform остаётся защитной составляющей
и отдельным контролем. При отсутствующем/некорректном расстоянии сборка
останавливается, отсутствующие признаки не подменяются нулевым расстоянием.
Для новых маршрутов s=uniform, поэтому p пропорционально sqrt(q), постоянно
по часам/типам дня; меняется масштаб маршрутного прогноза. Для четырёх B/F
маршрутов сохраняются 40 исходных часовых/будних/выходных профилей.

## Проверки и бюджет

До просмотра результатов фиксируются сравнения: alpha=0, 0.25, 0.75;
масштаб расстояния 300 и 800 м; lambda=0 и 10; равные доли. Отчёт TV по
каждому маршруту означает чувствительность, не ошибку и не доверительный интервал.
Новая временная оценка не проводится: нет независимых остановочных целей.
Исторические окна исследований и измерения маршрутного 030 не меняются.

Требуются полный набор 10×61×24 маршрутных часов, полная сетка позиций,
точный целочисленный баланс, ночные нули, отдельный статус route5 fallback,
неотрицательность, уникальность составных ключей, отказ при неполном входе,
нулевые exit-only, сохранение несопоставленной массы без перенормировки.
Проверить аналитическое решение и повторную побайтовую сборку. Бюджет —
локальный CPU, один основной выпуск и одна проверочная пересборка; GPU,
новый поиск моделей, backend/frontend, публикация и submission не входят.

## Передача

Один каталог готового выпуска и компактные входы сборки для GitHub, без ZIP.
Для использования не требуются raw оплаты, исходная служебная книга или
веса 030. Полное восстановление подготовленных признаков требует архивных
входов с хешами; обычная сборка использует зафиксированные производные входы.
Происхождение, лицензии OSM/архива метро и ограничения переносятся в metadata.
