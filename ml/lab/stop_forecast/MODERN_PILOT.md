Оба шаблона находятся **в одной группе `directions`** ответа. Индекс этой
группы нельзя использовать как направление движения. Ключ позиции —
`live:<path_uuid>:<num>`; UUID остановки может повторяться в разных позициях.
Происхождение, URL, время получения и SHA256:
[реестр снимков](sources/route12_live_20260927.json).
Способ поиска изучен в [закреплённой версии открытого клиента](https://github.com/ZhuravlevX/RailwaysTimetableTelegram/blob/e990405a3b085fb21180f8bd3f29ac7484669ea4/backend/src/routes/mostrans/suggest.rs);
чужой сервис не устанавливался и не запускался.

В ответе присутствует объявление №2645: с 26 сентября по выходным 11 и 12
укорочены до «Партизанской», вместо восточного участка — автобус 012к.
Основной список остановок при этом содержит Восточное Измайлово.
Поля `activeFrom`/`activeTo` сохранены буквально: они не объявлены точными
границами каждого фактически изменённого рейса. Состояние схемы и выполнение
рейса — отдельные признаки качества.

## Контрольный проход

Выбраны по одной позиции шести ориентиров в каждом шаблоне:
Первомайская, Партизанская, Семёновская, Авиамоторная, Пролетарская и МЦК
Дубровка. Если в направлении одноимённых позиций несколько, выбирается
первая по порядку. Это фиксированный технический набор, не выборка
для оценки пассажиропотока. Первомайская отмечена как контроль участка,
объявленного закрытым в выходные. Маркировка не устанавливает фактический ноль.

Первый полный проход: **12/12 ответов**, 80 ETA всех маршрутов,
26 по телеметрии и 54 по расписанию. Для №12 — **17 ETA, все по расписанию**.
Наличие расписания даже на объявленном закрытом участке показывает, почему
такое табло нельзя считать фактическими посещениями. Более ранний пробный
проход по трём остановкам дал ещё 4 ETA №12, также только по расписанию.
Данные хранятся локально в `dataset/external/route12_live_20260927/`.

Повторный проход: 12/12 ответов, ещё 18 ETA №12, также все по расписанию.
Вместе два прохода дали **35 записей ETA №12**, не 35 уникальных рейсов.
Прямой запрос к `api.moscowapp.mos.ru/v8.2/stop_v2` для Семёновской также
вернул только расписательный прогноз №12. Полные результаты и хеши —
[modern_pilot_results_20260927.json](sources/modern_pilot_results_20260927.json).
Все пары stop UUID / path UUID из ETA №12 присутствуют в полученной схеме.
Подготовка воспроизведена побайтово; нормализация обоих проходов повторена
из сохранённых исходных ответов с проверкой SHA256.

Техническое покрытие HTTP не равно покрытию движением или валидациями.
Время HTTP Date не доказывает свежесть исходной телеметрии. `tmId` не
приравнивается к гаражному номеру; совпадение `routePathId` со схемой
связывает прогноз с шаблоном, а не с выполненным рейсом.

## Условия следующего этапа

1. Проверить, появляется ли у №12 настоящая телеметрия/фактические координаты
   и доступны ли интервалы измерения и стабильные ключи. Если нет, не
   накапливать одни ETA под названием датасета движения.
2. Для независимого контроля нужны измерения из поездок или другой
   подтверждённый журнал фактических посещений. Сверка двух endpoint одного
   поставщика проверяет доставку, но не является независимым эталоном.
3. Для целевой переменной нужны успешные валидации за **тот же новый период**
   и связь устройства с вагоном. Самостоятельные подсчёты входящих, если они
   доступны, сохраняются отдельной целью, а не переименовываются в оплаты.
4. Только после получения контрольных наблюдений фиксировать обучение,
   выбор моделей и отдельный 61-дневный тест. Ни одна новая остановочная
   метрика пока не вычисляется.

Современный пилот разрешён; возможность свежих AFC или наблюдений в вагоне
уточняется. Без них текущий результат — проверенный набор схемы, объявлений
и опубликованных ETA с происхождением. Длительный сбор не запущен; фонового
процесса или обещания автономно накопить фактические посадки нет.

## Воспроизведение подготовки и одного прохода

```sh
.venv/bin/python ml/lab/stop_forecast/test_live_pilot.py
.venv/bin/python ml/lab/stop_forecast/prepare_live_pilot.py \
  --snapshot dataset/external/route12_live_20260927/route.json \
  --out /tmp/tramcast-live-pilot-new
```

Подготовка пишет `positions.json`, `roster.json`, `stop_ids.json`,
`service_alerts.json`, `summary.json` и `manifest.json`. Исходный ответ
содержит также геометрию `encodedPolyline`, сохранённую без преобразования.
Новый набор остановок проверяется перед следующим сбором; старые выходы
не перезаписываются. Для одного снимка использовать существующий
`collect_stop_evidence.py` с UUID из `stop_ids.json` и новым каталогом выхода.

Проверки: повторяющиеся остановки сохраняются; два шаблона одной группы
не объединяются; автобус с тем же номером, неверные координаты и повторные
порядковые ключи отклоняются. Исходные ответы и производные результаты
остаются вне Git, компактные реестры и отчёты доступны для ревью.
