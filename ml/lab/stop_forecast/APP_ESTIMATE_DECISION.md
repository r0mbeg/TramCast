# Решение: расчётное распределение посадок для приложения

27.09.2026 пользователь выбрал математически обоснованное сценарное
распределение как первую версию остановочной функции приложения. Это
допустимый продуктовый результат при имеющихся данных и открытых источниках;
его выпуск не требует ожидания дополнительных выгрузок от организаторов.
Исходная цель проверенной остановочной точности остаётся недостигнутой.
Backend/frontend и интеграция принадлежат другому разработчику. Публикация,
конкурсные посылки и изменение 030 этим решением не разрешены.

## Согласованный подход

Вход — версионированный прогноз успешных валидаций на маршруте за час,
выбранная версия схемы движения и явно заданные исходные доли. Распределение
строится энтропийным методом с сохранением маршрутных итогов. Уже есть
исследовательская KL-проекция F-v2; она не считается готовым интеграционным
пакетом и её точность по остановкам не измерена. Это не загрузка салона.

Утверждён способ получения оценок, а не конкретные веса: формулу исходных
долей q, их параметры и силу регуляризации ещё требуется закрепить в выпуске.
При ограничении только на сумму min KL(p||q) возвращает p=q; энтропия сама
не обучает остановочные доли. Равномерный prior остаётся контролем.
Признаковые веса без разметки — сценарные допущения. Ошибка маршрутного
итога не позволяет выбрать между нормированными распределениями.

## Условия готовности пакета

1. Маркировка «Расчётное распределение посадок». Пояснение: «Оценка по
   маршрутному прогнозу и предположениям модели; точность по отдельным
   остановкам не проверена». Не переносить маршрутный score на остановки.
2. Одна маршрутная сумма распределяется между направлениями, вариантами
   и позициями вместе. Повторное посещение сохраняет отдельный ключ.
   Альтернативные схемы нельзя молча считать одновременно обслуживаемыми:
   выбор схемы/веса вариантов и историческая применимость указываются явно.
3. Сохранять версию географии, происхождение ID и применимость к периоду.
   Поздняя схема допустима только с явным сценарным статусом. Отсутствие
   географии/неполный список позиций не означает нулевой спрос; неизвестный
   остаток сохраняется отдельно от остановок, а не распределяется принудительно.
4. По каждому часу сумма остановочных оценок и нераспределённого остатка
   равна входному маршрутному итогу. Целочисленные значения округляются
   согласованно по группе. Ночные нули и fallback №5 имеют отдельные причины.
5. Фиксировать версии маршрутной модели, схемы, метода распределения,
   исходных долей/параметров и источников. Оценки не использовать как факты
   для обучения. Диапазон чувствительности к prior не является калиброванным
   доверительным интервалом или измеренной точностью.
6. Передать другому разработчику локальный артефакт, схему и проверку
   суммы/ключей/покрытия. Саму интеграцию Go/UI в этой задаче не выполнять.

## Следующая реализация

Переиспользовать имеющийся расчёт долей, закрепить конкретный сценарий,
подготовить согласованный целочисленный экспорт и метаданные для пилотного
маршрута. До изменения кода представить подробный план. Затем описать перенос
на другие маршруты. Новые поиски источников не являются условием выпуска.
На момент этого решения новый интеграционный пакет ещё не подготовлен.
