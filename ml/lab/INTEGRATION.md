# ML-пакет TramCast: передача команде

## Что выдаёт сервис

Показатель — число успешных валидаций за календарный час маршрута после
очистки нерабочего времени. Это реализованные посадки; потенциальный спрос,
число людей в вагоне и заполненность по нему не определяются.

Действующий пакет **002 Chronos-2 daily zero-shot** сохранён. RPC читает
проверенные целые значения из CSV, без повторного обучения или инференса.
Конкурсный кандидат 031 и его ретроспективные внешние сведения остаются
отдельным исследовательским результатом. Новая проверка не выбирает модель
по дополнительным просмотренным окнам.

| Вопрос | Поддержка и предел |
|---|---|
| Маршрут |Номера 1,5,7,11,12,17,25,26,28,50; номер 5 — явно нулевой fallback|
| Период текущего пакета |01.11–31.12.2025, включая все ночные часы|
| Границы |`[from,to)`, целые часы Europe/Moscow;1–1464 часа на маршрут|
| День/неделя/месяц |Срезы одного пакета; все суммы из опубликованных часов|
| Произвольная дата запуска |Исследована на девяти исторических стартах; текущий RPC не создаёт новый пакет|
| Новые факты |Weekly проверен отдельно офлайн; не запускается переключением периода в UI|
| Год |Только отдельно маркированный сценарий; точность года не подтверждена 10 месяцами|
| Остановка/направление |Наблюдаемой цели нет; только явно названное сценарное распределение|
| Отсутствующие события |Не доказанный нулевой спрос; masks свидетельствуют о наличии, не полноте событий|

## Запуск и проверенный клиент

Из корня поставки/репозитория, Python3.12:

```sh
python3 -m venv ml/.venv
ml/.venv/bin/python -m pip install -r ml/requirements-service.txt
PYTHONPATH=ml/generated:ml ml/.venv/bin/python ml/service.py --bind 127.0.0.1:50051
```

В другом терминале — один день маршрута 1:

```sh
PYTHONPATH=ml/generated:ml ml/.venv/bin/python ml/client.py \
  --route 1 --from 2025-11-01T00:00:00+03:00 --to 2025-11-02T00:00:00+03:00 \
  --output /tmp/tramcast-route1-day.json
```

Весь пакет маршрута 50:

```sh
PYTHONPATH=ml/generated:ml ml/.venv/bin/python ml/client.py \
  --route 50 --from 2025-10-31T21:00:00Z --to 2025-12-31T21:00:00Z \
  --output /tmp/tramcast-route50-61days.json
```

В Compose адрес `ml:50051`, на хост порт по умолчанию не публикуется.
Без `--output` клиент печатает полный JSON. Deadline5 секунд; ошибки gRPC
возвращаются в stderr с кодом выхода 1, неверные аргументы —2. Клиент проверяет
версии, полную непрерывную сетку, наличие нулевого boardings и неотрицательность.
На Windows задать PYTHONPATH средствами используемой оболочки; при отсутствии
базы часовых поясов установить tzdata. Транспорт/авторизацию для внешнего
развёртывания настраивает команда backend.

## Версии и публикация

Источник API — `proto/tramcast/forecast/v1/forecast.proto`.
`ml/forecast_bundle.json` содержит фактические model_version/dataset_version,
SHA256CSV, конфигурацию и период. При публикации Go закрепляет ровно эти ID.
Сервер проверяет checksum, все 14640 ключей, int64, структурные нули и выдаёт
неизменяемый снимок. Подмена CSV под старым ID запрещена; новый пакет означает
новую версию и перезапуск сервиса.

Go сопоставляет внутренний ID с route_number, владеет очередью, дедлайнами,
повторами и транзакционной публикацией. Python не ходит в PostgreSQL.
`FAILED_PRECONDITION` — пакет повреждён/период вне него; `NOT_FOUND` — маршрут;
`INVALID_ARGUMENT` — границы; `UNAVAILABLE` — занят обработчик;
`RESOURCE_EXHAUSTED` — транспортный предел. Не заменять ошибку нулями.
Отмена и deadline прерывают построение ответа; успешных частичных ответов нет.

Для следующего пакета заранее закрепить origin и доступную историю, версию
очистки/наблюдений/внешних источников, рецепт и веса. Профили и коэффициенты
учатся только до origin; будущие целевые факты не входят в frozen прогноз.
Каждое регулярное обновление создаёт новый снимок с новым origin. Смена
активной версии не меняет версию уже начатого задания. Сейчас для нового
периода требуется отдельный офлайн выпуск; автоматического inference в RPC нет.

## Агрегации и сценарные коэффициенты

День = сумма 24 целыхчасов; неделя и месяц = сумма часов выбранного календарного
интервала вМоскве. Неполный месяц имеет подпись и реальные from/to. Не суммировать
округлённые заново дневные float-прогнозы и не смешивать версии. Weekday/date
вычисляются из hour_start в Europe/Moscow, а не из даты UTC.

Базовый прогноз и сценарий хранятся/показываются раздельно. Коэффициент
`k(route,date,hour)` должен быть конечным и≥0, с источником, автором, периодом
действия и основанием. Сценарий `floor(B*k+0.5)` строится как отдельная
производная величина от опубликованного B; после него сохраняются route5=0
и hours1–4=0. Его суммы — суммы полученных сценарных часов. Это не повторное
округление ответа RPC и не замена исторического факта. Если применяется сырой
ML-прогноз, округлять один раз после всех факторов и зафиксировать иной basis.

`k=0` для подтверждённой отмены обозначает нулевые посадки на этом номере,
но не исчезновение потенциальных пассажиров. Не задавать эластичность спроса
к выпуску/интервалу как измеренную без данных предложения. Температура,
событие и сезон могут иметь сценарные коэффициенты пользователя; текущая
модель не идентифицирует причинные эффекты и взаимодействия этих факторов.
Объявление после origin и фактическая будущая ERA5 допускаются в конкурсном
ретроспективном режиме, отдельно от информации на дату запуска.

Для годового сценария нужен отдельный явно заданный базис экстраполяции,
календарь, план движения и версия assumptions. Нельзя просто назвать повтор
двухмесячного пакета годовым прогнозом с проверенной точностью. Сервис 1464 часа
не обещает выдачу 365 дней; расширение требует отдельного согласования контракта.

## Остановочное распределение и необходимые данные

Для сценария задаются стабильные идентификаторы и доли `w(stop|route,direction,time)`,
`w≥0`, `Σw=1` на покрытом варианте. При целой сумме B можно распределить B*w
методом наибольших остатков с фиксированным порядком stop_id: сумма равна B,
ни одна точка не отрицательна. Направления сначала должны получить собственные
доли, суммирующиеся в 1; маршрутную сумму нельзя целиком копировать в каждое
направление. Это **сценарные оценки**, без метрики остановочного качества.
Такие величины не входят в текущий protobuf и таблицу маршрутных прогнозов.

Справочник 2025–2026 не гарантирует сеть на историческую дату; отсутствующая
география 17/25/26/28/50 не исключает их маршрутный прогноз. Нельзя достраивать
координаты или остановочные labels из названий и маршрутов.

Минимальные новые наблюдения: временная привязка AFC/валидатора квагону и рейсу,
AVL с координатами и остановками, versioned направления/трассы/время движения,
состояние валидаторов и покрытие, фактический выпуск/интервалы/отмены. Для
остановочной проверки — независимые stop×time посадки/APC на нескольких
режимах; для occupancy — ещё высадки и вместимость. Ненадёжный crd_hashcode
не становится идентификатором уникального пассажира. Для подтверждения годового
переноса нужны повторные полные годовые циклы и отдельный будущий период.

## Воспроизведение и ресурсы

Новая проверка и ограничения: `artifacts/methodology_20260927/REPORT.md`;
закреплённый протокол, направления, route/data/review — в том же каталоге.

Отдельный пакет для команды включает действующий CSV и SHA-манифест; веса
Chronos для обслуживания не нужны. Манифест не является цифровой подписью.

Проверки из ml:

```sh
PYTHONPATH=generated .venv/bin/python -m tests.test_service
PYTHONPATH=generated .venv/bin/python -m tests.test_client
```

Изкорня — микробенчмарк отдельного процесса действующего сервиса:

```sh
PYTHONPATH=ml/generated:ml ml/.venv/bin/python ml/benchmark_service.py \
  --samples 200 --output /tmp/tramcast-service-benchmark.json
```

Локальные замеры — loopback, CPU macOS, без CPUquota;1/24/720/1464 часа,
200 запросов, warmup10, конкуренция 1/4, INFO в файл. Это короткий микробенчмарк
CSV-serving, не нагрузочный SLA и не скорость Chronos inference. Время старта
отсчитывается после импортов; RSS — накопленный пик процесса. Успешный RPS/p95,
отказы и CPU публикуются отдельно; сеть, Go, БД, TLS и ресурсы 2vCPU/4GiB здесь
не проверяются. Сырые sample timings и архив исходника сохранены для проверки.
