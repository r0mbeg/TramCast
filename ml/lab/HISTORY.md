# ML TramCast

Python gRPC-сервис выдаёт готовый прогноз Chronos-2 из посылки **002**: 10 маршрутов, ноябрь–декабрь 2025, 14 640 почасовых значений. Модель уже рассчитана на Zhores; при запросах не нужны GPU, torch, исходные события или подключение к БД.

Сервис реализует [общий protobuf-контракт](../proto/README.md). Go отвечает за очередь, сопоставление ID маршрутов, версии и запись результатов. Go-клиент и полный сценарий публикации пока не реализованы.

Конкурсный портфель из семи проверенных прогнозов: [рейтинг и CSV](SOLUTIONS.md#актуальное-продолжение-goal-ещё-активен),
[исследование и воспроизведение](artifacts/portfolio_20260926/REPORT.md).

[Передача команде и примеры клиента](INTEGRATION.md),
[исследование применимости](artifacts/methodology_20260927/REPORT.md):
даты запуска, обновление фактов, ограничения года и остановок, независимая
проверка и фактические замеры ML-сервиса. Пакет002 сохранён.

## Запуск

Из корня репозитория, Python 3.12:

```sh
python3 -m venv ml/.venv
ml/.venv/bin/python -m pip install -r ml/requirements-service.txt
make run-ml PYTHON="$PWD/ml/.venv/bin/python"
```

Адрес по умолчанию — `127.0.0.1:50051`. Без Make, из `ml/`:

```sh
PYTHONPATH=generated .venv/bin/python service.py
```

В PowerShell из `ml/`: `$env:PYTHONPATH = 'generated'`, затем `.venv\Scripts\python service.py`. Если в системе нет базы часовых поясов, установите пакет `tzdata` в это окружение.

Для другого адреса или пакета: `python service.py --bind 127.0.0.1:50052 --bundle /path/to/forecast_bundle.json` с тем же `PYTHONPATH`. Пути файлов в метаданных считаются относительно самих метаданных. SIGINT/SIGTERM останавливают сервер с ожиданием активных вызовов до 5 секунд.

В Docker из корня:

```sh
docker compose up -d --build ml
```

Внутри Compose адрес — **`ml:50051`**. Порт не публикуется на хост; Python не получает секреты PostgreSQL. Образ содержит только сервер, protobuf-код и выбранный CSV. Параметры PostgreSQL в `.env` нужны для разбора общего Compose-файла, но запуск ML не запускает БД. Для отдельной сборки без Compose: `docker build -f ml/Dockerfile -t tramcast-ml .`.

## Контракт и пакет

`ForecastService.Predict` принимает номер маршрута и два Timestamp: **[начало, конец)**, выровненные по московскому часу. Для всего конкурсного периода: `2025-10-31T21:00:00Z` → `2025-12-31T21:00:00Z`. На маршрут возвращаются 1 464 точки, включая нули.

- Поддержаны `1, 5, 7, 11, 12, 17, 25, 26, 28, 50`. Номер 5 и часы 01–04 имеют нулевые значения с явно присутствующим `boardings`.
- Допустим полный период или его непрерывный срез. Другая дата — `FAILED_PRECONDITION`, неизвестный маршрут — `NOT_FOUND`, неверные границы — `INVALID_ARGUMENT`.
- [forecast_bundle.json](forecast_bundle.json) содержит версии модели и данных, конфигурацию Chronos, период и SHA-256 [посылки 002](submissions/002_chronos_daily_zero_shot.csv). Версия модели включает хеш конфигурации, версия данных — SHA-256 очищенной истории. Go должен закрепить именно эти ID в своей версии прогноза.
- CSV загружается один раз: проверяются SHA-256, схема, точная сетка, диапазон int64 и нули. Уже округлённые числа выдаются без изменений. Неправильный пакет не заменяется нулями: сервер пишет причину в лог и отвечает `FAILED_PRECONDITION`.
- Пакет неизменяем в памяти; для замены нужен перезапуск с согласованной новой версией. Не подменять содержимое файлов под прежними ID.
- Один обработчик строит ответ, занятый обработчик даёт `UNAVAILABLE`. Дополнительный транспортный предел — 8 одновременных RPC (`RESOURCE_EXHAUSTED` при превышении). Максимум — 1 464 часа; запрос до 64 KiB, ответ до 4 MiB. Отмена/deadline проверяются при построении каждой точки.

Сервис обслуживает сохранённый прогноз, а не вычисляет новый. Для другого горизонта потребуется новый пакет или отдельное подключение инференса. Округление half-up выполнено в ML-пайплайне при экспорте; дробный CSV сервис отвергает.

## Проверки и генерация

Из корня с указанным выше окружением:

```sh
make test-ml-service PYTHON="$PWD/ml/.venv/bin/python"
ml/.venv/bin/python -m pip install -r ml/requirements.txt
make test-ml PYTHON="$PWD/ml/.venv/bin/python"
```

Проверка сервиса открывает временный loopback-порт и сверяет все 14 640 значений с CSV через gRPC. Также проверяются границы, присутствие нуля, повреждения пакета, ошибки, занятость, отмена и deadline. Полный набор добавляет проверки очистки, отсутствия утечек, WAPE, half-up и экспериментов без загрузки Chronos. Для необязательного теста бустингов установите `requirements-boost.txt` и из `ml/` выполните `PYTHONPATH=generated python -m tests --boost`.

Сгенерированный Python-код уже включён. После изменения единственного исходника в `proto/`:

```sh
ml/.venv/bin/python -m pip install -r ml/requirements-proto.txt
make proto-generate-python PYTHON="$PWD/ml/.venv/bin/python"
```

Файлы `generated/` не редактируются вручную. Генератор и runtime закреплены в requirements-файлах.
