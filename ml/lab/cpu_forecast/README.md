# Самостоятельный CPU-прогноз по наблюдениям

CatBoost обучается на реальных успешных валидациях из очищенной истории.
Ответы 030 не используются ни как цели обучения, ни для выбора настроек.
GPU не нужна при обучении или выдаче. Основной микросервис 030 не переключён.

Вход — любая дата начала в 2025 году и имеющаяся очищенная история.
Выход — следующие **61 сутки**, 10 маршрутов × 24 часа = 14 640 строк.
Поздний старт может пересекать 2026 год: результат не обрезается, но этот
переход помечается как непроверенная экстраполяция. Время Europe/Moscow.

## Как устроено обучение

Исторические старты берутся с 29 января с шагом 10 дней; дополнительно
добавляется последний старт, чей полный 61-дневный горизонт заканчивается
точно на границе обучения. В признаки каждого примера идут только факты
до его старта, а цели целиком лежат до границы обучения. Используются только
ячейки с `working_events_observed=True`; восстановленные и отсутствующие
счётчики не превращаются в наблюдения.

Признаки: календарь, час, маршрут, дальность, прошлые часовые профили
за всю историю / 112 / 28 дней, уровень маршрута и доступность истории.
Сохранённый календарь движения — разрешённый ретроспективный внешний сценарий.
Для №50 применяется существующее правило нулей на осенних выходных закрытия.
Погода и прогнозы других моделей не требуются.

CatBoost предсказывает отношение спроса к прошлому профилю. Потери взвешены
так, чтобы учитывать ошибку в количестве валидаций, с поправкой на повторение
одного целевого часа в нескольких горизонтах. Две конфигурации и доля модели
в смеси с профилем (0.5 / 1.0) фиксируются до расчёта.

- Выбор настроек: обучение до 30 апреля → май–июнь; до 30 июня → июль–30 августа.
- Основная проверка: обучение до 31 августа → весь сентябрь–октябрь,
  без обновления фактов внутри этих 61 суток и без подбора по этому окну.
- Итоговая модель: переобучение выбранного рецепта с границей 31 октября.
  Январские факты до 29 января используются в признаках; цели начинаются 29 января.

Проверенные ранее периоды не являются новым независимым тестом. Сходство
с 030 не оптимизируется; сохранённый 030 читается только для итогового сравнения.

## Запуск

Из корня репозитория, после установки [зависимостей](requirements.txt):

```sh
.venv-boost/bin/python -m ml.lab.cpu_forecast.model \
  --bundle ml/lab/artifacts/cpu_forecast_20260927_v2/bundle \
  --history ml/lab/artifacts/hourly_clean.csv \
  --start 2025-11-01 \
  --output /tmp/tramcast-cpu-november
```

Каталог результата должен быть новым. Выход — `forecast.csv` и обязательный
`forecast.json` с версией, границами, датой использованных наблюдений и
ограничениями. Это самостоятельный CLI; HTTP/gRPC-интеграция не добавлена.

История: `route;date;hour;boardings;working_events_observed`. Дополнительные
колонки допускаются. Ключи уникальны, значения целые неотрицательные, маска
True/False. Час 5 уже должен быть очищен по 05:30; CSV сырых событий этот
запуск не обрабатывает. Будущие строки относительно выбранного старта
игнорируются при вычислении исторических признаков.

Итоговые веса обучены по октябрь включительно. Поэтому запрос на прошедшую
дату — ретроспективное применение этих весов, **не причинный backtest**.
Для проверки сентября–октября сохранён отдельный пакет `evaluation/`,
обученный только по август включительно.

Для января почти нет предшествующей истории: модель использует обученный
резервный режим с отсутствующими историческими признаками. Его качество
для начала года не подтверждено. Для поздних стартов история может устареть;
свои прогнозы модель не добавляет к фактам. Календарь праздников и движения
2026 года неизвестен и передаётся как NaN. Все эти случаи отмечаются в JSON.

Сохраняются half-up, неотрицательность, int64, нули №5 и часов 1–4. Файл
модели нативный `.cbm`, с проверкой SHA256; pickle не используется. Пакет
должен поступать от доверенного оператора.

## Воспроизведение

```sh
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 VECLIB_MAXIMUM_THREADS=2 \
  .venv-boost/bin/python -m ml.lab.cpu_forecast.train \
  --output ml/lab/artifacts/cpu_forecast_repeat

.venv-boost/bin/python -m ml.lab.cpu_forecast.test_model \
  --bundle ml/lab/artifacts/cpu_forecast_20260927_v2/bundle
```

Каждый запуск обучения требует нового каталога. Протокол сохраняет источники,
версии библиотек, параметры, лимит 30 минут и два CPU-потока до обучения.
При проверке подменяются будущие факты и ненаблюдаемые счётчики: ни обучающая
выборка, ни предсказание не должны измениться.

Переиспользуются функции чтения/признаков прежнего `cpu_student/model.py`;
его учитель, веса и прогнозы в выдаче не нужны. Для переноса нужны текущий
`model.py`, указанный модуль признаков, `ml/runtime/constants.py`, пакет
`bundle/`, очищенная история и CPU-зависимости. Готовый архив содержит их.

[Результаты и ограничения](../artifacts/cpu_forecast_20260927_v2/REPORT.md).

## LightGBM Laplace

Отдельный опыт заменяет CatBoost на LightGBM `regression_l1`: это оценка
положения Laplace с фиксированным масштабом (MAE), без обучения масштаба
и интервалов неопределённости. Признаки, цели, веса, маски, два окна выбора
и сентябрьско-октябрьская проверка сохранены. Библиотека уже есть в
`.venv-boost`; версии — [requirements-lightgbm.txt](requirements-lightgbm.txt).

```sh
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 VECLIB_MAXIMUM_THREADS=2 \
  .venv-boost/bin/python -m ml.lab.cpu_forecast.lightgbm_laplace \
  --output ml/lab/artifacts/lightgbm_laplace_repeat
```

Каталог должен быть новым. Результаты: нативные `forecast.lgb`, параметры
`metadata.json`, контрольные проверки, метрики и `submission.csv` на
ноябрь–декабрь. `predict` в этом модуле принимает загруженный `lightgbm.Booster`,
метаданные, очищенную историю и дату начала. Это отдельный формат модели;
CLI CatBoost с `.cbm` его не загружает.
